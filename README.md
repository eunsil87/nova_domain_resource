# NOVA Focal 인력관리

폐쇄망 Windows VDI에서 Edge·Chrome으로 실행하는 오프라인 인력관리 앱입니다. 현재 기능 명세인 [docs/SPEC.md](docs/SPEC.md)와 `design/`의 화면 초안을 기준으로 관리합니다. 서버·로그인·외부 DB·CDN·별도 런타임을 사용하지 않습니다.

## 사용하기

1. `dist/NOVA.html`을 VDI의 앱 폴더에 복사합니다.
2. Edge 또는 Chrome에서 해당 HTML을 엽니다. 기준 화면은 1920×1080, 배율 100%입니다.
3. 처음에는 **앱 폴더 연결**을 누르고 HTML을 둔 폴더를 선택합니다. 권한을 허용한 다음 새 워크스페이스 생성을 확인합니다.
4. 이후에는 같은 폴더의 `nova-data.json`을 불러옵니다. 브라우저가 권한을 다시 요구하면 재확인합니다.
5. 팝업 **적용**은 현재 세션에만 반영합니다. 상단 **저장**을 눌러 실제 JSON 파일에 저장합니다.

앱 업데이트 시 `NOVA.html`만 교체하고 기존 `nova-data.json`은 유지합니다. 한 데이터는 한 탭에서 사용합니다. HTML과 JSON을 같은 앱 폴더에 보관하세요. 브라우저에 기억하는 것은 폴더 연결이며 인력 데이터 원본은 JSON입니다. `.exe` 실행 허용 여부와 무관하게 HTML 방식으로 배포합니다.

## 구현 범위

- 연간 현황: 참고 Phase 일정, 연도별 목표, M/M 집계·그래프, 14/30일 일정, 부족 인원 계산 및 TBD 추가
- 인력 관리: 등록·상세 수정·삭제, 예정/실제 등록, TBD 등록·전환, 기본/헤더 정렬, 종료 인력 표시, 모든 추가 정보
- 그룹 설정: 다중 구성안·복사·비교·적용, 인력 그룹·상위 그룹·리더, 드래그 배치, 개발반장, 복수 현장대리인
- 기본 설정: 프로젝트·파트 이름, 업체·역할·기술 추가·수정·비활성화
- 저장: 수동 저장, 시작 시 자동 정리와 단일 저장, 파일 변경 충돌 확인, 저장 실패 시 세션 유지, 손상/최신 스키마 데이터 보존

확정 인력 14명과 TBD 5명, 빈 1안을 최초 생성할 때만 제공합니다. 기존 파일의 빈 목록을 초기 상태로 간주해 채우지 않습니다. 2026년 최초 목표는 65.000 M/M이고 확정 예상 실적은 76.000, TBD 계획은 10.000 M/M입니다. 실제 실행일의 한국 날짜로 TBD·자격을 처리하므로 날짜가 지나면 값은 달라집니다.

일반 자동 저장, 백업 파일, 변경 이력, 검색·복합 필터, 인력별/그룹별/월별 M/M, 공동 편집, 작업량·일정 배분은 포함하지 않습니다. Catalog의 Sub Component 담당자 연결은 지원합니다.

## 개발하기

개발에만 Node.js 22 이상과 npm이 필요합니다. 최종 사용자는 설치하지 않습니다.

```sh
cd /workspace/nova_domain_resource
npm ci --ignore-scripts --cache /workspace/.npm-cache
npm run build
npm test
npm run test:browser
npm run test:browser:groups
npm run test:browser:catalog
npm run test:browser:roles
```

Windows 등 다른 개발 머신에서는 기본 npm 캐시를 사용해 `npm ci --ignore-scripts`를 실행해도 됩니다. 브라우저 테스트에는 설치된 Chromium이 필요합니다. 기본 경로는 `/usr/bin/chromium`이며 `CHROMIUM_PATH`로 실제 실행파일 경로를 지정할 수 있습니다. 테스트는 임시 로컬 HTTP 서버를 스스로 시작·종료합니다. 앱 실행에 이 서버는 필요하지 않습니다.

- `src/core.js`: 초기 데이터·날짜·정밀 M/M·인력 검증·직책/그룹 참조 처리
- `src/storage.js`: File System Access API·연결 기억·안전한 쓰기 완료·충돌 확인
- `src/app.js`, `src/style.css`: 화면·팝업·세션 편집·드래그
- `scripts/build.mjs`: 소스와 스타일을 단일 HTML로 묶음. 외부 자산을 생성하지 않음
- `tests/`: 계산/저장 테스트 및 브라우저 기능 시나리오
- `docs/SPEC.md`: 변경사항을 계속 반영하는 현재 기능 명세
- `docs/VALIDATION.md`: 검증 결과와 VDI 확인 항목
- `docs/SCHEMA.md`: 데이터 구조와 버전 정책

작업은 기존 체크아웃에서 진행합니다. 사용자가 요청하지 않는 한 별도 Git worktree를 만들지 않습니다.

## 검증 범위

Node 테스트 64개와 Chromium 브라우저 시나리오 72개(기본 28 + 그룹 13 + Catalog 18 + 단일 담당자/Phase 13)가 통과했습니다. 브라우저 테스트는 실제 네이티브 파일 핸들·파일 스트림·IndexedDB를 사용하지만, OS 폴더 선택 창은 테스트용 브라우저 디렉터리(OPFS)로 대체합니다. 이는 Windows의 로컬 HTML 파일과 VDI 폴더에서 검증한 결과가 아닙니다.

사용자가 확인한 사전 VDI 파일 접근 가능 여부와 별개로, 이 배포 파일의 Edge·Chrome 실사용 검증은 `docs/VALIDATION.md`의 체크리스트에 따라 수행해야 합니다. 동시 저장 직전 비교는 서버식 잠금이 아닙니다.

## Git 관리

GitHub 저장소는 `eunsil87/nova_domain_resource`, 기본 개발 기준 브랜치는 `main`입니다. 소스·테스트·요구사항·화면 참고 자료와 바로 실행할 수 있는 `dist/NOVA.html`을 함께 관리합니다. `node_modules`, 테스트 결과, 사용자 데이터 `nova-data.json`, 배포 ZIP과 중복된 release 폴더는 제외합니다.

수정 후 `npm test`, `npm run build`, 화면 동작에 영향이 있으면 `npm run test:browser`를 실행하고 소스와 갱신된 HTML을 함께 커밋합니다. GitHub Actions는 main push와 pull request에서 계산·저장 테스트 및 빌드 결과 일치 여부를 검사합니다. 브라우저 테스트는 별도의 개발 환경 검증입니다.

## 그룹 배치 사용법 (0.1.1)

- 그룹 제목의 ⠿를 다른 독립 그룹 카드 **가운데**로 드래그하면 두 그룹이 선택된 상위 그룹 만들기 팝업이 열립니다. 이름을 입력하고 적용합니다. 취소하면 배치를 변경하지 않습니다.
- 그룹을 기존 상위 그룹의 제목이나 하위 카드 가운데로 드래그하면 그 상위 그룹 안으로 이동합니다.
- 그룹 카드의 **가장자리**에 놓으면 파란 삽입선 위치로 순서를 변경합니다. 상위 그룹도 제목을 잡아 다른 항목 앞뒤로 이동할 수 있습니다.
- 하단의 **상위 그룹 밖으로 꺼내기** 영역에 놓으면 인력 그룹을 유지한 채 독립 배치합니다.
- 배치는 조회 중인 구성안에만 적용됩니다. 상단 **저장**을 눌러야 파일에 반영되며 저장 후 다시 열어도 순서를 유지합니다.

업데이트는 기존 `nova-data.json`을 유지하고 `NOVA.html`만 교체합니다. 이전 파일에 배치 순서 항목이 없으면 기존 표시 순서를 그대로 사용합니다.

## 전체 Phase에서 오늘 위치 보기 (0.1.2)

연간 현황의 맨 위에서 전체 설계·개발 기간을 한 시간축으로 봅니다. 파랑은 설계, 청록은 개발이며 오늘은 붉은 세로선으로 표시합니다. 오늘을 포함한 기간은 테두리와 '기간 중' 표시로 강조하고 상단에 해당 Phase와 작업 구분을 함께 안내합니다. 막대에 포인터를 올리거나 키보드로 포커스하면 정확한 기간을 확인할 수 있습니다.

조회 연도를 바꿔도 전체 Phase와 오늘 위치는 유지합니다. 한국 날짜가 바뀌면 표시만 갱신하며 파일을 자동 저장하거나 인력 일정을 바꾸지 않습니다. 일정 밖 날짜는 시작 전/종료 후, 구간 사이 날짜는 현재 해당 기간 없음으로 표시합니다. 일정표와 참고 일정 표시는 유지합니다. 이는 달력상 위치이며 실제 작업 완료율을 기록하는 기능은 아닙니다.

기능 변경 시 `docs/SPEC.md`의 해당 규칙·검증 기준·버전·갱신일·변경 이력을 같은 커밋에 갱신합니다. 데이터 구조와 검증 결과, 사용법 문서도 함께 맞춥니다.

## Catalog 관리 (0.2.0 당시 사용법)

아래는 이전 버전의 사용법 기록입니다. 현재 단일 담당자·Phase와 전환은 아래 0.3.0 절을 따릅니다.

1. HTML을 교체하고 기존 데이터를 연 뒤 **Catalog 관리** 메뉴를 선택합니다.
2. **서비스오더 v3.0으로 시작**을 확인하면 도메인 3개·L2 5개·Sub Component 12개·L3 20개·L4 106개를 불러옵니다. 다른 업무는 **빈 Catalog로 시작**할 수 있습니다.
3. 계층별 탭, 상위 필터, 하위 보기와 검색으로 탐색합니다. 각 계층에서 추가·수정·삭제하고 L4 설명·필수/옵션도 편집합니다.
4. Sub Component의 **담당자** 버튼에서 여러 인력 또는 TBD를 연결합니다. 하위 항목이 있으면 먼저 이동/삭제하고 담당자가 있으면 연결을 해제한 뒤 항목을 삭제합니다.
5. 적용은 세션 변경이며 상단 **저장**으로 같은 JSON에 반영합니다. 처음 Catalog를 적용하면 새 스키마 2가 저장되므로 이후에는 Catalog를 지원하는 새 HTML을 사용합니다.

기존 인력·그룹·M/M는 유지합니다. 기준 자료 원본은 `docs/catalog/`, 생성기는 `scripts/import-catalog.mjs`, 독립 로직은 `src/catalog.js`에 있습니다. 자료를 재생성하려면 `npm run catalog:generate`를 실행하고 변경된 기준 JS와 빌드 HTML을 함께 검증합니다. 업무 항목 변경은 보통 앱 화면에서 하며 Git의 기준 자료를 바꿀 필요가 없습니다.

## Catalog 명세·시안 이력 (SPEC 0.27 작성 시점)

[현재 SPEC](docs/SPEC.md)의 11.3.5~11.3.8과 [Catalog 레이아웃 시안](design/catalog-layout-v0.27.png)에 다음 변경을 정리했습니다. 이 절은 0.27 작성 당시 미구현 상태의 시안 기록입니다. 현재는 아래 0.3.0 절과 SPEC 0.28을 따릅니다.

- L2 영문 명칭, Sub Component·L3·L4 한글 명칭을 주 표시명으로 사용
- L4마다 단일 Phase 1/2/3 또는 미지정
- SC·L3·L4 설계자 각각 한 명, L4 개발자 한 명; 모두 TBD 지정 가능
- SC 설계자 A→B 변경 시 하위 L3/L4 중 현재 인력 ID가 A인 항목만 B로 변경
- 인력별 할당 시각화는 추가 대상이나 집계 단위는 아직 미확정

기존 복수 담당자 전환과 미지정/해제·상위 이동 경계는 SPEC 13.4의 확인 항목으로 남겼습니다. 수정사항은 모아 두고 사용자의 구현 요청 때 반영합니다.

## 단일 설계·개발 담당자와 Phase (0.3.0)

기존 JSON을 유지하고 HTML을 교체합니다. 기존 0.2.0 Catalog가 있으면 **Catalog 관리 → 담당자 방식 전환**에서 SC별 설계자 한 명을 확인합니다. 복수 담당자는 직접 선택하고 이전 전체 목록은 전환 전 정보로 보존합니다. 적용 후 **저장**을 눌러야 파일에 반영됩니다.

- L2는 영문, Sub Component·L3·L4는 한글 명칭으로 표시합니다. 신규/상세 수정의 한글은 필수이고 기존 영문은 참고 자료로 유지합니다.
- SC 설계자 A→B는 현재 A인 하위 L3/L4만 B로 바꿉니다. 다른 사람은 유지하며 SC 미지정/해제도 같은 값 비교를 적용합니다. 확인 취소는 변경하지 않습니다.
- L3와 L4는 설계자를 개별 변경할 수 있습니다. L3 단독 변경은 L4로 전파하지 않고 새 L4의 설계자는 SC에서 기본 지정합니다.
- L4의 개발자와 단일 Phase 1/2/3/미지정은 목록에서 선택합니다. 설계·개발 모두 TBD가 가능하고 같은 인력도 두 구분에 지정할 수 있습니다.
- 상위 필터에서 SC와 L3를 고르면 시안처럼 컨텍스트 영역을 보여줍니다. 목록 선택은 세션에 즉시 적용하고 파일은 상단 저장으로 반영합니다.
- 신규/전환 파일은 전체 스키마 3, Catalog 구조 2를 사용하므로 저장 후에는 새 HTML로 계속 사용합니다. 기존 1/2 형식은 읽기 지원합니다.
- **할당 현황 그래프는 집계 기준 미확정으로 보류**하며 버튼은 비활성입니다.
