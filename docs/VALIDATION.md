브라우저 테스트의 폴더 선택 창은 OPFS 디렉터리로 대체합니다. 그 이후의 FileSystemDirectoryHandle, getFile, createWritable, write/close, IndexedDB 연결 핸들 저장·복원은 실제 브라우저 API입니다. 실패·충돌은 의도적으로 주입해 확인합니다. 별도로 Node 저장 계층 테스트에서 write/close 실패와 이전 원문 보존을 검사합니다.

클라우드에 설치된 Chromium의 정책이 `file://` 탐색을 차단하므로 브라우저 자동 테스트에서는 테스트 프로세스가 시작·종료하는 로컬 HTTP 서버를 사용했습니다. 브라우저 정책을 변경하거나 우회하지 않았습니다. 앱에는 HTTP 서버가 필요하지 않습니다. Windows Edge·Chrome에서 이 HTML 파일을 직접 열어 검증한 것은 아닙니다.

## 사용자에게 확인받은 VDI 사전 조건

- Windows, 1920×1080, 배율 100%
- 로컬 HTML 실행 가능
- 폴더 선택 가능
- JSON 생성·수정·다시 열기 가능
- 재접속 후 폴더 권한 재확인 가능

이는 개발 전 환경 점검 결과입니다. 아래는 이번 완성 파일로 추가 확인할 항목입니다.

## VDI 인수 체크리스트 — 아직 실행하지 않음

- [ ] Edge에서 `NOVA.html`을 열고 같은 앱 폴더를 연결한다.
- [ ] 새 데이터 생성 후 확정 14명/TBD 5명/빈 1안/목표 65.000을 확인한다.
- [ ] 조회 연도 2026에서 초기 확정 예상 실적 76.000을 확인한다. 초기 TBD 시작일이 지난 날에 검증하면 TBD 값은 날짜 규칙에 따라 달라진다.
- [ ] 인력 상세의 가사번 앞자리 0·IPv4 네 칸·메모를 입력한다. 적용 전/적용 후/저장 후 상태를 구별한다.
- [ ] 저장 후 탭을 닫았다가 같은 HTML을 열어 변경 내용이 복원되는지 확인한다.
- [ ] VDI 재접속 후 권한이 유지되거나 재확인 동작으로 연결되는지 확인한다.
- [ ] Chrome에서 동일 항목을 확인한다. 같은 데이터는 동시에 두 탭에서 편집하지 않는다.
- [ ] 쓰기 권한을 회수했을 때 저장 실패·미저장 유지·폴더 재연결 후 재시도를 확인한다.
- [ ] 긴 이름과 메모, 표 스크롤 및 모든 팝업 하단 버튼이 잘리지 않는지 확인한다.
- [ ] 필요한 경우 테스트용 데이터 폴더에서 두 탭 충돌·시작 시 TBD 정리·대표 인계 선택/취소를 확인한다.

선택·원자적 참조 처리의 자동화 검증이 실제 VDI 보안 정책·디스크 오류 동작 전체를 보장하지는 않습니다. Sub_Component 배정은 합의한 후속 범위입니다.

원문의 도메인 3개, L2 5개, Sub Component 12개, L3 20개, L4 106개(필수 86/옵션 20)를 대조했습니다. 항목 ID·한글/영문 명칭·기능 설명·부모 경로를 원문 행 단위로 검증합니다. 직접 관리 화면에서 ID/부모 변경 후 하위 내부 참조와 담당자가 유지되고, 하위 항목 및 담당자가 남으면 삭제가 차단됩니다.

Catalog 선택 전에는 기존 인력·그룹·JSON을 변경하지 않습니다. Catalog 최초 적용은 세션의 스키마 2 전환이고 전역 저장에서 파일에 반영합니다. 인력 삭제 시 담당자 연결 안내와 해당 참조 정리, TBD 확정 시 연결 유지, 자동 TBD 삭제 시 연결 정리, 종료 인력의 기존 연결 보존도 확인했습니다. 초기 원본으로 다시 채우지 않습니다.

브라우저 테스트는 기존과 같이 OS 선택 창을 실제 OPFS 디렉터리 핸들로 대체합니다. 파일 스트림·IndexedDB는 실제 API를 사용하고 실패를 주입합니다. 현재 클라우드 실행 제한에서 일반 `node --test`는 개별 테스트 대신 파일 단위만 보고하고 로컬 포트는 EPERM으로 차단되어, 권한이 허용된 실행에서 55개 개별 테스트와 브라우저 59개 시나리오의 실제 완료를 확인했습니다. 단순 파일 개수 5개 결과를 테스트 통과로 산정하지 않았습니다.

이번 배포 HTML의 Windows VDI 직접 실행 및 실제 폴더 쓰기는 사용자 환경에서 추가 확인해야 합니다. Catalog를 저장한 데이터는 스키마 2를 지원하는 새 HTML로 사용합니다.

## SPEC 0.27 문서·시안 갱신 — 2026-10-27

변경 범위는 SPEC·관련 안내와 레이아웃 이미지입니다. 명칭 표시, 단일 Phase, 단일 설계/개발 담당자, SC A→B 값 일치 전파는 아직 앱 코드/HTML/저장 스키마에 반영하지 않았습니다. 할당 현황 집계 기준과 기존 복수 담당자 전환 등은 SPEC 13.4에 미확정으로 남깁니다.

이번에는 문서 내부 규칙·버전·상대 링크·미구현 상태와 Git diff를 확인합니다. 실행 코드가 바뀌지 않아 애플리케이션 테스트를 다시 실행하지 않으며, 기존 0.2.0 테스트 통과 기록을 새 요구사항 검증 결과로 사용하지 않습니다. 시안 이미지는 Windows VDI 실행 검증 결과가 아닙니다.
