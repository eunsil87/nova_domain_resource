검증일: 2026-10-22 (한국 날짜). 기준 SPEC v0.24, 초기 앱 0.1.0.

## 자동 검증

| 검증 | 결과 | 범위 |
| --- | --- | --- |
| `npm run build` | 통과 | 단일 오프라인 HTML 생성, 1 MB 이내 |
| `npm test` | 29/29 통과 | 초기 집계, 날짜/윤년/기간, 정밀 M/M, 필요 인원, TBD 정리·전환, 업체 잠금, 복수 대표 인계·철수, 그룹 참조, 저장 완료·실패·충돌·손상 보호 |
| `npm run test:browser` | 26/26 시나리오 통과 | 실제 Chromium DOM 조작, 네 화면, 팝업·중첩 복귀, JSON 스트림 쓰기/재실행, 드래그, 저장 실패/재시도, 충돌, 시작 처리 차단·원자적 인계 |
| 외부 네트워크 | 요청 0건 | 앱 실행 중 외부 자산·API 요청 없음. CSP에서도 연결 금지 |
| 기준 화면 | 확인 | 1920×1080, 콘텐츠 영역 중심 팝업, Phase 표 상단, IPv4 네 번째 칸 및 메모 포함 |

브라우저 테스트의 폴더 선택 창은 OPFS 디렉터리로 대체합니다. 그 이후의 FileSystemDirectoryHandle, getFile, createWritable, write/close, IndexedDB 연결 핸들 저장·복원은 실제 브라우저 API입니다. 실패·충돌은 의도적으로 주입해 확인합니다. 별도로 Node 저장 계층 테스트에서 write/close 실패와 이전 원문 보존을 검사합니다.

클라우드에 설치된 Chromium의 정책이 `file://` 탐색을 차단하므로 브라우저 자동 테스트에서는 테스트 프로세스가 시작·종료하는 로컬 HTTP 서버를 사용했습니다. 브라우저 정책을 변경하거나 우회하지 않았습니다. 앱에는 HTTP 서버가 필요하지 않습니다. Windows Edge·Chrome에서 이 HTML 파일을 직접 열어 검증한 것은 아닙니다.

## 사용자에게 확인받은 VDI 사전 조건

- Windows, 1920×1080, 배율 100%
- 로컬 HTML 실행 가능
- 폴더 선택 가능
- JSON 생성·수정·다시 열기 가능
- 재접속 후 폴더 권한 재확인 가능

이는 개발 전 환경 점검 결과입니다. 아래는 이번 완성 파일로 추가 확인할 항목입니다.

## VDI 인수 체크리스트 — 아직 실행하지 않음

- [ ] Edge에서 `NOVA.html`을 열고 같은 앱 폴더를 연결한다.
- [ ] 새 데이터 생성 후 확정 14명/TBD 5명/빈 1안/목표 65.000을 확인한다.
- [ ] 조회 연도 2026에서 초기 확정 예상 실적 76.000을 확인한다. 초기 TBD 시작일이 지난 날에 검증하면 TBD 값은 날짜 규칙에 따라 달라진다.
- [ ] 인력 상세의 가사번 앞자리 0·IPv4 네 칸·메모를 입력한다. 적용 전/적용 후/저장 후 상태를 구별한다.
- [ ] 저장 후 탭을 닫았다가 같은 HTML을 열어 변경 내용이 복원되는지 확인한다.
- [ ] VDI 재접속 후 권한이 유지되거나 재확인 동작으로 연결되는지 확인한다.
- [ ] Chrome에서 동일 항목을 확인한다. 같은 데이터는 동시에 두 탭에서 편집하지 않는다.
- [ ] 쓰기 권한을 회수했을 때 저장 실패·미저장 유지·폴더 재연결 후 재시도를 확인한다.
- [ ] 긴 이름과 메모, 표 스크롤 및 모든 팝업 하단 버튼이 잘리지 않는지 확인한다.
- [ ] 필요한 경우 테스트용 데이터 폴더에서 두 탭 충돌·시작 시 TBD 정리·대표 인계 선택/취소를 확인한다.

선택·원자적 참조 처리의 자동화 검증이 실제 VDI 보안 정책·디스크 오류 동작 전체를 보장하지는 않습니다. Sub_Component 배정은 합의한 후속 범위입니다.
