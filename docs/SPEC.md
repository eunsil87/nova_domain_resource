# NOVA Focal 인력관리 앱 명세

버전: 0.24 최종 규칙·사용 흐름 점검본  
갱신일: 2026-10-21 KST  
상태: 최종 합의 규칙과 화면 흐름 정합성 점검본. 구현·실환경 검증 및 시안의 한계는 13절에 분리한다.

## 1. 목적과 범위

차세대 프로젝트의 업무 파트 리더 Focal이 인력, 투입 계획, 연간 M/M, TBD 및 그룹을 관리한다. 인력관리부터 실사용 가능한 수준으로 완성하고 후속 기능을 확장한다.

- Focal 혼자 자신의 업무 파트를 등록·수정한다. 인력 본인이 접속해 정보를 입력하는 기능, 공동 편집, 다중 사용자 권한 관리는 제외한다. Focal의 인력 수동 등록·수정은 기본 기능이다.
- 다른 업무 파트에서도 독립적으로 사용할 수 있어야 한다. 한 데이터 묶음은 한 프로젝트의 한 업무 파트를 대상으로 한다. 프로젝트·파트·인력·업체는 설정 데이터로 관리하며 코드에 고정하지 않는다. 기본 설정의 프로젝트·파트 관리는 이 데이터 묶음의 이름과 기본값 관리이며, 다중 프로젝트·파트 전환 기능을 뜻하지 않는다.
- 최초 사용자용 프로젝트명은 `NOVA`, 파트명은 `Service Order(무선)`이다.
- 여러 파트의 통합 조회·인력 공유는 제외한다.
- 업무 할당 단위는 `Sub_Component`이나 상세화 및 구현은 후속 범위다.

## 2. 환경과 파일

- PC의 폐쇄망 VDI에서 Edge·Chrome으로 사용한다.
- VDI 개인 폴더는 종료·재접속 후에도 유지된다.
- 개인용 서버·공유폴더를 사용할 수 없다. 외부 서버·DB·로그인·인터넷에 의존하지 않는다.
- 별도 프로그램이나 런타임 설치 없이 로컬 HTML 파일을 열어 실행한다.
- HTML 앱 파일과 JSON 데이터 파일을 분리한다. 앱 교체 후 기존 데이터를 불러올 수 있어야 한다.
- 실행 자산을 함께 제공한다. CDN, 외부 API·폰트·이미지 의존성을 두지 않는다.
- 사진·첨부파일, 누적 변경 이력·로그는 첫 버전에서 제외한다.
- M/M 등 계산 가능한 집계는 중복 영구 저장하지 않고 계산한다.
- 백업 만들기 기능과 자동 백업은 첫 버전에서 제외한다. 별도 백업 파일을 생성하지 않는다.
- 앱 파일 1MB 이내를 우선 경량화 목표로 삼는다. 이는 설계 목표이며 실제 크기는 구현 후 확인한다.
- 사용자는 VDI 폴더에 별도 권한 부여 신청 없이 접근하고 직접 저장할 수 있다고 확인했다. 브라우저의 폴더 선택·파일 API 권한 확인은 별개이며 실제 VDI에서 검증한다.
- 브라우저 내부 저장소를 유일한 데이터 원본으로 사용하지 않는다. PC 간 자동 동기화는 제외한다.
- HTML과 데이터 JSON을 같은 앱 폴더 안에 둔다. 최초 실행 시 앱 폴더를 한 번 연결하고 이후 연결 정보를 기억해 재연결을 시도한다.
- 일반 사용자는 파일의 존재와 경로를 의식하지 않도록 한다. 평상시 파일 선택·경로·저장소 기술 정보를 노출하지 않는다.
- 브라우저 권한 재확인 또는 연결 단절 시에만 `앱 폴더 연결`을 안내한다. 소스에 경로를 지정하는 것만으로 브라우저 파일 접근 권한을 대체할 수 없다. 무조건 자동 재연결을 보장하지 않는다.

## 3. 수동 저장과 시작 시 자동 처리

### 3.1 일반 작업

1. 최초 한 번 앱 폴더를 연결한다. 이후에는 기존 연결을 이용해 폴더 안의 데이터에 접근한다. 첫 사용 데이터 생성과 기존 데이터 연결은 사용자에게 파일 관리 작업을 강요하지 않는 흐름으로 구성한다.
2. 앱 화면에서 조회·등록·수정한다. 사용자가 JSON을 직접 편집할 필요는 없다.
3. 일반 변경 사항은 저장 버튼을 눌러 같은 파일에 반영한다. 일반 자동 저장은 하지 않는다.
4. 미저장 여부를 표시하고 저장 성공 후에만 저장 완료로 표시한다. 실패하면 미저장 상태를 유지한다.
5. 데이터 초기화·연결 전환 등으로 미저장 작업을 버리게 되는 동작이 있으면 `저장 후 진행 / 저장하지 않고 진행 / 취소`를 제공한다. 일반 화면에는 파일 열기·다른 파일 선택을 주 작업으로 배치하지 않는다. 저장 실패·취소 시 현재 데이터를 유지한다.
6. 브라우저 새로고침·종료 시 미저장 변경이 있으면 가능한 범위에서 브라우저 기본 경고를 사용한다. 브라우저 정책상 경고 문구와 표시 여부를 앱이 완전히 제어할 수는 없다.
7. 조회 연도·표 정렬·종료 인력 표시 옵션 변경은 데이터 수정으로 취급하지 않는다. 메뉴 이동만으로 적용된 세션 변경을 버리지 않는다. 그룹 드래그 배치는 데이터 변경이다.
8. 팝업 초안 → 적용된 세션 데이터 → 저장된 JSON을 구분한다. 검증 실패 또는 팝업 취소는 세션 데이터를 변경하지 않는다. 관련 인력·그룹·직책 참조 변경은 적용 시 함께 반영한다.

### 3.2 실행 및 새로고침 시 처리

데이터 파일 접근 권한 확보 후, 메인 화면 표시 전에 아래 작업을 수행한다. 새로고침도 동일하며 파일에 저장된 데이터를 기준으로 시작한다.

1. 한국 날짜 기준으로 예상 시작일이 오늘 이하인 TBD의 시작일을 조정하고, 조정 결과 최소 기간 미충족인 TBD를 삭제한다. 미래 TBD를 단순히 잔여 기간이 줄었다는 이유로 삭제하지 않는다.
2. 모든 구성안을 대상으로 삭제 인력의 인력 그룹·그룹 리더·상위 그룹 리더 및 공통 현장대리인·개발반장 참조를 정리한다. 종료일이 오늘보다 이전인 확정 인력을 그룹에서 자동 제외하고 그룹 리더 지정을 해제한다. 구성원이 남으면 리더 미지정, 빈 그룹이면 자동 삭제한다. 미확정 TBD에 확정 인력의 종료 상태 규칙을 적용하지 않는다.
3. 종료된 현장대리인·개발반장 지정을 해제한다. 현장대리인은 9절의 기존 대표 우선 인계 및 최초 지정 규칙, 개발반장은 자동 승계 없는 공석 규칙을 적용한다. 투입 상태와 M/M를 재평가한다.
4. 자동 처리로 영구 데이터가 변경된 경우 같은 JSON 파일에 즉시 저장.
5. 메인 화면 표시.

이 시작 시 자동 처리는 수동 저장 원칙의 예외다. 정상 결과 알림과 요약은 표시하지 않는다. 자동 처리 중 TBD 삭제에 따른 그룹 리더 알림과 현장대리인 자동 승계 알림도 생략한다. 후보 선택 등 사용자 결정이 필요한 경우만 별도 입력을 받는다. 실패 시에는 오류를 알려야 하며 저장 성공으로 처리하지 않는다. 변경이 없으면 불필요하게 다시 저장하지 않는다.

날짜 경과에 따른 영구 데이터 자동 정리는 실행·새로고침 시 처리한다. 상태·자격·일정 등 파생 조회값은 한국 날짜로 계산한다. 수동 편집으로 현재 자격이 사라지면 적용 시 관련 참조를 함께 정리하고 다음 실행까지 잘못된 배정을 유지하지 않는다. 수동 편집 내용과 자동 저장을 섞지 않는다. 연결 또는 브라우저 접근 권한이 없으면 앱 폴더 연결 전에 실제 파일 변경은 불가능하다.

### 3.3 오류와 충돌 처리

- 데이터 손상·형식 오류가 있으면 원본을 덮어쓰거나 빈 데이터로 자동 초기화하지 않는다.
- 시작 시 자동 처리 저장에 실패하면 메인 편집 화면으로 넘어가지 않고 오류와 `재시도`를 제공한다.
- 연결이 끊긴 경우에만 `앱 폴더 연결`을 추가 안내한다. 기본 오류 동작을 `다른 파일 선택`으로 두지 않는다.
- 앱이 지원하지 않는 최신 스키마를 임의 변환하지 않는다. 데이터 호환 처리는 명시적인 스키마 버전으로 구분한다.
- 동일 데이터는 한 탭 사용을 기본으로 한다. JSON의 저장 버전 번호를 보관하고 저장 직전에 파일의 현재 버전을 다시 읽어 비교한다.
- 열었던 버전과 현재 버전이 다르면 덮어쓰기 저장을 중단하고 새로고침을 안내한다. 버전은 성공적으로 저장할 때 증가시킨다.
- 버전 비교는 동시 저장의 모든 경쟁 상태를 완벽히 막는 서버식 잠금은 아니다. 첫 버전은 이 한계를 전제로 단일 탭 사용과 저장 직전 비교를 제공한다.
- 사용자 저장뿐 아니라 시작 시 자동 저장에서도 오래된 데이터로 덮어쓰지 않도록 같은 충돌 방지 원칙을 적용한다.
- 시작 시 정리는 원본을 읽은 작업 사본에서 전체 수행한다. 사용자 선택과 검증이 모두 완료된 뒤 한 번 저장하고 메인을 표시한다. 중간 결과만 저장하지 않으며 선택 취소 시 원본을 유지하고 재시도 가능한 시작 화면으로 돌아간다.
- 명세 버전, JSON 구조의 스키마 버전, 파일 저장 때 증가시키는 저장 버전은 서로 다른 값이다. 스키마 변경이 없어도 저장 버전은 증가할 수 있다.
- 실제 파일 쓰기 완료 후에만 저장 성공으로 표시한다. 저장 도중 실패하면 세션 변경을 유지하고 기존 파일을 의도적으로 지우거나 빈 데이터로 대체하지 않는다. 지원 API에서 가능한 안전한 쓰기 완료 방식을 사용하되 별도 백업 파일은 만들지 않는다.

## 4. 인력 항목과 입력

| 항목 | 형식 및 규칙 |
| --- | --- |
| 내부 ID | 레코드별 고유 식별자. 동명이인·재투입 구분 |
| 이름 | 확정 인력 이름 |
| TBD 표시명 | 기본 `TBD#1`, `TBD#2`… 자동 부여, 직접 수정 가능 |
| 직원 타입 | 업체 매핑에서 자동 산출하는 조회값. 인력 입력 항목 아님. 정직원 / BP / AGS, 업체 미정이면 null |
| 업무 역할 | 정직원은 Focal 선택 가능 및 역할 공란 허용. AGS·BP는 설정된 역할 선택(초기값 설계자 / 개발자) |
| 기술 구분 | 기본 설정의 기술 값 선택. 초기값 F/S / B/E / F/E, F/S는 양쪽 가능 |
| 업체 | 인력 소속 업체 |
| 현장대리인 | AGS·BP 업체별 지정. 역할·기술이 다른 경우 같은 업체에 복수 선임 가능(9절) |
| 그룹 | 구성안별로 최대 한 인력 그룹. 미배정 허용. 인력 목록에서는 적용 중인 안의 소속 표시 |
| 투입 시작일 | TBD는 예상 시작일 |
| 투입 종료 예정일 | 기본 `9999-12-31`. 실제 철수 시 종료일 수정 |
| SKT 가사번 | 선택. `P` + 숫자 6자리 |
| DOSS ID | 선택. `DS` + 숫자 6자리 |
| DeVDI IP | 선택. IPv4 한 개 |
| MyDesk IP | 선택. IPv4 한 개 |
| Local IP | 선택. IPv4 한 개 |
| 좌석번호 | 선택. 영문·숫자·기호를 허용하는 텍스트 |
| 메모 | 선택. 줄바꿈 가능한 간단한 자유 텍스트 |

### 4.1 필수값

- 확정 인력: 이름·업체·투입 시작일 필수. 직원 타입은 선택한 업체에서 자동 결정하며 별도 입력하지 않는다. 정직원은 SKAX 등 정직원 타입에 연결된 업체를 사용한다.
- AGS·BP 확정 인력: 업체·업무 역할·기술 구분도 필수.
- 정직원: 역할·기술 구분 선택 입력.
- TBD: 표시명·예상 시작일 필수. 업체·역할·기술 구분은 선택이다. 직원 타입 입력란은 없고 업체 미정 시 타입도 null이다. 업체를 지정하면 해당 업체의 타입을 자동 적용한다. 종료일은 기본값 적용 가능하다.
- 종료일 미입력 시 `9999-12-31` 적용.
- 그룹 및 추가 정보는 선택이다.
- 일반 미입력 선택값은 JSON `null`로 저장하고 화면에는 빈칸으로 표시한다. `NULL` 문자나 하이픈을 출력하지 않는다.

### 4.2 가사번과 ID

- 입력란에 `P`와 `DS`를 고정 표시하고 사용자는 뒤의 숫자 6자리만 입력한다.
- 숫자는 문자열로 처리하여 앞자리 0을 유지한다. 빈 숫자 부분은 미등록이다.
- 입력하면 정확히 숫자 6자리인지 검사한다.
- 저장·조회는 접두어를 포함한 전체 값이다. 예: `P028315`, `DS005041`.
- 위 값은 형식 예시이며 실제 초기 인력에 임의 배정하지 않는다.

### 4.3 IPv4

- 네 개의 숫자 입력 칸 사이에 점을 고정 표시한다. 점을 직접 입력할 필요가 없다.
- 각 칸은 숫자만, 0~255 범위다.
- Tab으로 다음 칸, 마지막 칸에서는 다음 입력 항목으로 이동한다.
- 모두 비어 있으면 null. 일부 칸만 입력되거나 범위를 벗어나면 오류다.
- 저장 시 `192.168.0.10` 같은 하나의 문자열로 관리한다.
- 가사번·DOSS ID·IP·좌석번호 등 추가 정보의 중복 검사·경고는 구현하지 않는다. 해당 검증을 위한 기간 비교와 교차 항목 비교도 제외한다.
- 접두어·숫자 칸·IPv4 분할 입력 등 이미 합의한 기본 입력 방식은 유지한다. 별도의 복잡한 추가 정보 검증 시스템은 만들지 않는다.

### 4.4 날짜

- 달력 선택 및 숫자 8자리 입력을 모두 지원한다. `20261101` → `2026-11-01`.
- 존재하지 않는 날짜와 시작일보다 앞선 종료일은 오류다.
- `9999-12-31`은 데이터에 유지하되 목록 등 화면의 종료일 표시에서는 빈칸으로 보인다.
- 종료일 빈칸은 일반 null과 달리 미정 종료일 기본값 의미다.
- 시작일·종료일 모두 포함해 최소 15일 투입이어야 한다.
- 실제 인력의 조기 철수는 15일 미만이라도 허용하고 실제 기간으로 M/M를 계산한다.
- 등록 팝업은 기본으로 `투입 예정 등록`, 이미 실제 투입한 인력을 입력할 때는 `실제 투입 정보` 모드를 제공한다. 표시 상태는 입력 날짜에서 산출하며 모드를 별도의 인력 상태로 저장하지 않는다.
- 신규 TBD·투입 예정 인력의 시작일은 내일 이후만 허용한다. 오늘과 과거 날짜는 달력에서 비활성화하고 직접 숫자 입력도 차단한다.
- 11절 초기 데이터, TBD 확정 전환뿐 아니라 이미 실제 투입한 인력을 뒤늦게 등록하는 경우에도 오늘·과거 시작일을 허용한다. 신규 예정 인력 등록과 실제 투입 정보 등록을 구분하며, 예정으로 등록하면서 미래일 제한을 우회하지 않게 한다.
- 확정 인력의 실제 일정 정정은 오늘·과거 시작일을 허용한다. 미확정 TBD를 유지한 채 시작일을 오늘·과거로 직접 수정하는 동작은 차단한다. 날짜 도래 시에는 기존 자동 조정 규칙을 적용한다. 실제 투입 이후에는 시작일 정정으로 업체 잠금을 해제하지 않는다.

## 5. 투입과 상태

- 투입 한 건을 독립 레코드로 관리한다. 같은 사람이 재투입되면 새로 등록하고 이름 중복을 허용한다.
- 동일인 통합·재투입 이력 연결·변경 이력 저장은 제외한다.
- 역할·기술은 인력 원본의 현재 값, 그룹 배정은 구성안별 현재 값만 관리한다. 과거 시점별 조직도·역할 이력 복원은 제공하지 않는다.
- 인력에서 직원 타입은 직접 변경할 수 없는 업체 기반 조회값이다. 확정 인력은 업체를 변경할 수 있는 투입 전에도 기존과 같은 타입의 업체만 선택하며 업체를 비울 수 없다. TBD는 업체 변경에 따라 타입도 자동 갱신되며 업체를 비우면 타입도 null이다.
- 업체는 확정 인력의 투입 시작일 당일부터 종료 후까지 수정 불가다. 아직 투입을 시작하지 않은 확정 예정 인력과 TBD는 수정 가능하되 위 타입 제한을 따른다. 잠금 여부는 편집 전 상태를 기준으로 검증해 시작일을 미래로 먼저 수정하는 방법으로 업체 잠금을 우회하지 못하게 한다. 실제 투입 경험 여부를 잠금용 상태로 유지해 시작일을 미래로 정정해도 업체 잠금은 유지한다. 정정 결과의 표시 상태는 날짜로 산출하되 변경 이력 전체를 누적하지 않는다.
- 종료일 조정으로 실제 철수 처리한다. 예정 투입 취소·TBD 취소는 별도 취소 상태 없이 삭제한다. 오등록은 수정 또는 삭제한다.

| 표시 상태 | 한국 날짜 기준 |
| --- | --- |
| 투입 예정 | 오늘 < 시작일인 확정 인력 |
| 투입 중 | 시작일 ≤ 오늘 ≤ 종료일인 확정 인력 |
| 종료 | 종료일 < 오늘인 확정 인력 |
| TBD | 아직 확정되지 않은 계획 인력 |

## 6. TBD 계획과 확정 전환

- TBD 한 건은 한 명이다. 여러 명이 필요하면 여러 건 등록한다.
- 기본 표시명 번호는 현재 사용하지 않는 가장 작은 양의 정수를 재사용한다. 예: TBD#1, TBD#3 존재 시 다음은 TBD#2.
- TBD 표시명은 TBD끼리 중복 불가다. 표시명과 별개로 내부 ID는 고유하게 유지한다.
- 기간·업체·역할·기술은 공통 인력 원본으로, 그룹 배정은 구성안별로 관리한다.
- 그룹 구성원과 그룹 리더 모두 가능하다.
- 확정 전환 시 기존 레코드를 이어받아 이름과 필수 정보를 입력한다. 기간·업체는 허용 범위 안에서 함께 수정 가능하다.
- 직원 타입과 관계없이 확정 전환은 이름·업체·시작일 필수다. AGS·BP로 확정하면 역할·기술도 필수이며, 정직원은 역할·기술을 비울 수 있다. 전환 확정 전에는 TBD이므로 기존 업체가 있어도 확정 인력의 타입 잠금을 선행 적용하지 않는다.
- 확정 전환은 신규 예정 등록과 구분한다. 실제 투입 시작일은 오늘·과거·미래 모두 허용하며 시작일과 종료일에 따라 즉시 투입 중·종료·투입 예정 상태를 산출한다. 신규 TBD·예정 인력 등록의 내일 이후 제한을 전환에 적용하지 않는다.
- 과거 실제 투입일 입력 시 자동 조정된 TBD 날짜를 실제 날짜로 수정할 수 있다. 최소 15일 원칙을 적용하되 실제 조기 철수는 기존 예외를 따른다.
- 내부 인력 ID·그룹·그룹 리더·유효한 현장대리인 지정을 유지하고 새 인력을 중복 생성하지 않는다. 전환 결과가 이미 종료된 확정 인력이면 종료 인력의 그룹 제외·그룹 리더 해제 규칙을 적용 시 함께 반영한다. 현장대리인은 9절의 업체 및 자격 규칙도 충족해야 하며, 업체 변경 시 기존 업체의 직책을 해제·승계하고 새 업체로 직책을 자동 이월하지 않는 9절 규칙을 따른다.
- TBD 계획 M/M에서는 제외하고 연말 예상 실적에 포함한다.

### 6.1 자동 시작일 조정

실행·새로고침 시 예상 시작일이 오늘이거나 지난 미확정 TBD만 대상으로 한다.

| 오늘 | 새 예상 시작일 |
| --- | --- |
| 1~14일 | 당월 15일 |
| 15일~말일 | 익월 1일 |

- 오늘보다 미래인 TBD와 확정 인력은 변경하지 않는다.
- 기존 종료일은 유지한다.
- 조정 후 시작일부터 종료일까지 양 끝 날짜 포함 15일 미만이면 TBD를 자동 삭제한다. 종료일이 시작일보다 앞선 경우도 포함한다.
- 정확히 15일이면 유지한다. 예: 11/1~11/15 유지, 11/1~11/14 삭제.
- `9999-12-31`은 최소 기간을 충족하는 정상적인 미정 종료일로 처리한다.
- 삭제 시 그룹에서 제거하고 마지막 구성원이라면 그룹도 삭제한다. 리더가 삭제되고 구성원이 남으면 리더 미지정이다.
- 정상 결과 알림 없이 파일에 반영한다. 삭제·정리 대상 전체를 먼저 계산해 인계 후보에서 제외하고 남은 인력만으로 참조를 정리한다. 여러 대표 중 인계 대상 선택이 필요하면 9절의 예외를 적용한다.

## 7. 연간 M/M

- 한 사람은 투입 기간에 100% 투입으로 계산한다. 별도 투입률 항목은 두지 않는다.
- 정직원·BP·AGS 모두 연간 목표와 실적에 포함한다.
- 월 전체는 1.000 M/M, 월 중간은 달력 일수 기준으로 계산한다.
- 시작일과 종료일 모두 포함한다. 해당 연도와 겹치는 기간만 계산한다.
- M/M 입력과 표시 정밀도는 소수점 셋째 자리다. 연간 목표는 0 이상의 숫자이며 미입력은 null이다. 반올림은 음수가 아닌 기여값에 대해 소수점 넷째 자리에서 일반 반올림한다. 집계는 정수 0.001 M/M 단위 또는 동등한 정밀 연산으로 계산해 부동소수점 오차로 올림 인원이 달라지지 않게 한다.
- 각 월의 계산값은 중간 반올림하지 않고 인력별 연간 값으로 합산한 다음 소수점 넷째 자리에서 반올림해 셋째 자리로 만든다.
- 전체·직원 타입별·TBD 집계는 이렇게 산출한 인력별 연간 값을 합산한다. 월별 중간 반올림을 하지 않는다.
- 인력별 연간 M/M는 합계 산출을 위한 내부 계산값일 뿐 목록·상세 등 사용자 화면에 표시하지 않는다.
- 월은 계산 단위일 뿐 화면에 월별 M/M 표를 제공하지 않는다.
- 종료일이 조회 연도 밖이거나 `9999-12-31`이면 해당 연도 12/31까지 계산한다. 9999년까지 반복 계산하지 않는다.
- 집계는 항상 조회 연도 전체 기간 기준이며 앞으로 남은 기간만을 뜻하지 않는다. 조회 연도와 투입 기간이 겹치지 않으면 0.000이다.
- 직원 타입은 업체 ID의 매핑에서 파생한다. 확정 인력은 업체 필수이므로 타입별 합계가 전체와 일치한다. 업체 미정 TBD도 전체 TBD 계획에는 포함하되 정직원·BP·AGS 확정 예상 실적에 섞지 않는다.

| 지표 | 규칙 |
| --- | --- |
| 연간 목표 | 연도별 전체 하나, 직접 입력 |
| 연말 예상 실적 | 종료·현재·확정 예정 인력의 연간 M/M 합계. TBD 제외 |
| 타입별 예상 실적 | 정직원 / BP / AGS 합계. 전체와 일치 |
| TBD 계획 M/M | 별도 집계, 실적과 구분 |
| 목표 대비 차이 | 예상 실적 - 목표. 부족·초과 표시 |

- NOVA / Service Order(무선)의 2026년 연간 목표 초기값은 **65.000 M/M**이다. 정직원·AGS·BP 전체 합계 목표 한 개로 관리하고, 다른 연도는 별도 입력 전까지 미설정(null)이다. 기존 파일에 입력·수정한 목표를 실행 시 초기값으로 덮어쓰지 않는다.
- 목표 미입력은 0이 아니라 null이며 `목표 미설정` 표시. 실적은 계산하되 목표 대비 차이는 계산하지 않는다.
- 그룹별 M/M 집계는 제공하지 않는다.
- 종료 인력을 목록에서 숨겨도 해당 연도 실적에서 제외하지 않는다.

| 계산 사례 | 결과 |
| --- | --- |
| 2026-04-01~04-30 | 1.000 |
| 2026-04-16~04-30 | 15/30 = 0.500 |
| 2026-03-16~03-31 | 16/31 → 0.516 |
| 2026-10-01~9999-12-31, 2026년 조회 | 3.000 |

### 7.1 연간 현황 그래프

- 연간 현황에 조회 연도 기준의 가로 누적 막대그래프를 제공한다. 월별 추이는 추가하지 않는다.
- 확정 인력의 연말 예상 실적과 TBD 계획을 서로 다른 색·범례·수치로 구분한다. 확정 실적은 파란색, TBD는 구별되는 황색 계열을 사용한다.
- 막대 구간은 확정 예상 실적 + TBD 계획이며 합산값은 실적이 아니라 계획 합계라고 명시한다. TBD가 확정 실적으로 오인되지 않게 표시한다.
- 2026-10-17 기준 초기 검산값은 확정 76.000, TBD 10.000, 계획 합계 86.000 M/M이다. 실행일·연도·데이터 변경 후에는 재계산하며 화면에 상수로 고정하지 않는다.
- 연간 목표가 설정되면 같은 축에 목표선을 추가한다. 목표가 미설정이면 목표선과 달성률을 표시하지 않고 목표 미설정을 안내한다. 숫자 0 목표와 미설정을 구분하고, 0 목표일 때 달성률은 나누기 오류 없이 미표시한다.
- 수치 축은 M/M, 0부터 시작한다. 목표·실적·계획 합계 중 최대값을 포함하도록 범위를 자동 조정한다. 시안의 0~100은 현재 초기 데이터용 축이지 목표 100을 의미하지 않는다.
- 모든 수치 레이블은 소수점 셋째 자리, 연도·인력·TBD·기간 변경 시 기존 집계와 함께 재계산한다.
- 막대가 짧거나 0인 경우에도 범례와 수치로 내용을 확인할 수 있어야 한다. 색상만으로 의미를 구분하지 않는다.
- 그룹별·인력별 M/M 그래프는 추가하지 않는다. 대용량 차트 라이브러리나 외부 CDN 없이 SVG/CSS 등 가벼운 방식으로 구현한다.

### 7.2 다가오는 투입 및 철수 요약

- 연간 현황에서 가까운 투입·철수를 간단히 확인한다. 기본 기간은 향후 30일이며 14일/30일 선택을 제공한다.
- 이 기간은 조회 연도의 연간 M/M 집계와 달리 오늘부터의 일정이다. 카드에 한국 날짜 기준 기간을 명시한다.
- 확정 투입 예정, TBD 예상 투입, 확정 인력 철수 예정 건수를 구분한다. TBD를 확정 투입 인원에 합치지 않는다.
- 확정 투입 예정은 오늘 < 시작일 ≤ 오늘+선택일수, 철수 예정은 오늘 ≤ 종료일 ≤ 오늘+선택일수로 구분하며 종료 미정 9999-12-31은 제외한다. TBD도 미래 예상 시작일을 같은 범위로 비교한다.
- 일정보기 팝업은 날짜순으로 이름·투입/철수/TBD 구분·업체·역할을 보여주고 행 클릭 시 해당 인력의 상세 팝업을 연다. 인력 상세를 닫으면 일정 팝업으로, 일정 팝업을 닫으면 원래 연간 현황으로 복귀한다. 확정 인력 한 명이 범위 안에서 투입과 철수 모두 해당하면 두 일정으로 표시하고 각각 집계한다.
- 2026-10-17 기준 30일 내 확정 투입 예정은 박훈·조기웅 2명, TBD 5명, 철수 0명이다. 14일 선택 시 11/1은 범위 밖이다.
- 대상이 없으면 0명으로 표시하고 자동 알림창을 띄우지 않는다. 실행·새로고침과 인력 일정 수정 후 갱신한다.

### 7.3 목표 부족분 필요 인원 계산

- 연간 현황의 필요 인원 계산 버튼에서 작업 영역 중앙 팝업을 연다.
- 연도 목표·확정 예상 실적·기존 TBD 계획을 보여주고 가정 투입 시작일·종료일을 입력한다. 시작일은 신규 TBD와 같이 내일 이후, 종료일 기본값 9999-12-31, 양 끝 포함 최소 15일 규칙을 적용한다.
- 조회 연도 내 부족 M/M를 기준으로 인원을 계산한다. 범위 밖 날짜는 조회 연도와 겹치는 부분만 사용한다.
- 확정 기준 부족분 = max(연간 목표 - 확정 예상 실적, 0).
- 기존 TBD 반영 후 부족분 = max(연간 목표 - 확정 예상 실적 - 기존 TBD 계획, 0).
- 두 기준을 나란히 표시해 기존 TBD가 계획에 있는지 확인할 수 있게 한다. 실제 추가 TBD 등록은 기본적으로 기존 TBD 반영 후 결과를 사용한다.
- 가정 기간의 1명당 연간 기여 M/M는 기존 달력 기준 계산과 동일하다. 필요 인원 = ceil(부족 M/M / 1명당 연간 기여 M/M). 필요 인원은 정수, 기여 M/M는 소수점 셋째 자리다.
- 반올림된 M/M를 기존 집계와 동일하게 사용하며 추가 후 목표를 충족하는지 계산 결과를 재검산한다.
- 연간 목표 미설정 시 인원 숫자를 추측하지 않는다. 목표 설정 동작을 제공하고 목표가 지정된 후 계산한다.
- 부족분이 0이면 기간 기여가 0이어도 필요 인원은 0명이다. 부족분이 양수인데 조회 연도와 기간이 겹치지 않거나 1명당 기여가 0이면 나누지 않고 기간 확인 안내를 표시한다.
- 결과에서 TBD 등록으로 연결하되 바로 데이터를 늘리지 않는다. 예상 기간·등록할 정수 인원 수를 확인한 뒤 개별 TBD 건으로 생성한다. 업체·역할·기술은 선택값이며 직원 타입 입력은 없다. 업체 미정 등록이면 타입도 null이다.
- 등록 수를 수정할 수 있고 기본값은 기존 TBD 반영 후 필요 인원 수다. 최종 확인 전에는 인력·실적·파일을 변경하지 않는다. 등록 이후에도 일반 수동 저장을 적용한다.
- 계산은 목표 충족을 위한 인원 환산이며 업무량·생산성 또는 특정 기술 인력의 적정 수를 자동 판정하는 기능은 아니다.

## 8. 그룹 설정

- 인력 목록과 별도의 그룹 설정 화면에서 그룹별 구성을 관리한다. 인력을 직접 배정하는 기존 그룹은 이하 인력 그룹, 그룹들을 묶는 단위는 상위 그룹이라 부른다. 이 절의 기존 구성원·리더·빈 그룹 처리 규칙은 인력 그룹을 기준으로 하며 상위 그룹은 8.3절을 따른다.
- 인력 그룹명 기본값은 `Group#1`, `Group#2`…이며 직접 수정 가능하다. 상위 그룹명은 직접 입력한다.
- 자동 번호는 해당 구성안에서 현재 사용하지 않는 가장 작은 양의 정수를 재사용한다. 인력 그룹·상위 그룹 이름은 같은 구성안 안에서 중복 불가하며, 서로 다른 구성안에서는 같은 그룹명을 사용할 수 있다. 그룹 내부 ID와 표시 번호는 분리한다.
- 그룹은 구성원 최소 한 명이며 생성 시 리더 한 명을 지정한다. 이후 삭제·이동·투입 종료로 리더가 빠지면 공석(null)을 허용하고 저장할 수 있다. 구성원은 남았는데 리더가 없다는 이유로 그룹을 자동 삭제하거나 저장을 막지 않는다. 정직원·AGS·BP·TBD와 모든 업무 역할에서 리더·구성원을 선택할 수 있다.
- 한 인력은 각 구성안 안에서 최대 한 인력 그룹에 소속된다. 다른 구성안에서는 다른 그룹·리더·미배정 상태를 가질 수 있다. Focal은 그룹에 속하지 않아도 되며 미배정 경고 대상에서 제외한다.
- 개별 그룹 리더는 해당 그룹의 구성원이어야 한다. 개발반장만 맡을 때는 그룹 소속이 필요 없으며, 개별 그룹 리더를 겸임하면 그 그룹의 구성원이어야 한다.
- 종료된 확정 인력은 새 그룹 구성원·리더 선택 및 드래그 배정 대상에서 제외한다.
- 리더 외 설계자·개발자 수는 제한하지 않는다. 설계자나 개발자가 반드시 있어야 하는 조건은 없다.
- 인력 한 명 이상 선택 후 그룹 생성. 한 명이면 자동 리더 지정, 여러 명이면 리더 선택.
- 그룹과 그룹 내 구성원 순서를 드래그로 변경한다. 리더는 그룹 안 맨 위에 표시한다.
- 드래그로 미배정 → 그룹 배정, 그룹 간 이동, 그룹 → 미배정 해제를 지원한다.
- 리더 지정은 별도 동작이다. 역할 변경은 리더 지정에 영향을 주지 않는다.
- 리더 삭제·이동 후 구성원이 남으면 리더 미지정 상태를 허용하고 Focal이 직접 후임을 정한다. 자동 승계하지 않는다.
- 마지막 구성원이 삭제·이동되어 빈 그룹이면 자동 삭제한다.
- 그룹을 직접 삭제하면 구성원 데이터는 유지하고 소속과 리더 지정만 해제한다.
- 사용자가 인력 그룹 또는 상위 그룹 리더 인력을 삭제하면 `해당 인력 삭제 시 (그룹명) 확인 필요`를 표시한다. 여러 안·그룹에 걸치면 한 확인 팝업에 안 이름과 그룹별 문구를 함께 보여준다. 예: 2안의 `해당 인력 삭제 시 Group#1 확인 필요`. 확인 후 모든 안에서 정리하고 동일 알림을 연속으로 띄우지 않는다.
- 시작 시 TBD 자동 삭제는 위 개별 알림 없이 처리하는 예외다.
- 종료일 당일까지 소속과 리더 지정을 유지한다. 종료일 이후 최초 실행·새로고침 시 인력을 그룹에서 자동 제외하고 리더 지정도 해제한다. 인력 기록과 M/M는 유지한다.
- 그룹 설정의 미배정 목록은 투입 중 → 투입 예정 → TBD 순으로 정렬하고, 같은 상태 안에서는 10.1절의 직원 타입·역할·기술·기간·이름 순서를 적용한다. 인력 관리의 평면 목록 정렬과 그룹 내 저장된 드래그 순서는 서로 별개다.


### 8.1 전체 그룹 총괄 개발반장

- 개발반장은 업무 파트 전체 그룹의 리더인 선택 직책이다. 최대 한 명을 지정하며 필수 자리가 아니므로 공석(null)을 허용한다.
- 초기값은 유원기 인력 레코드이며 변경·지정 해제 가능하다. 표시 이름 대신 내부 인력 ID로 연결한다. 개발반장은 업무 파트 전체의 공통 직책으로 구성안별로 별도 복제하거나 변경하지 않는다. 개별 그룹 리더·상위 그룹과 구별한다.
- 특정 그룹에 속해도 되고 그룹 미배정이어도 된다. 전체 그룹의 총괄이라는 이유로 여러 그룹에 중복 소속시키지 않는다.
- 선택 대상은 현재 투입 중인 확정 인력만이다. 한국 날짜 기준 시작일 ≤ 오늘 ≤ 종료일이어야 한다. TBD·투입 예정·종료 인력은 선택 불가다.
- 개발반장 지정은 기존 설계자/개발자 역할, 직원 타입, 기술 구분, 그룹 리더, 현장대리인과 별개다. 유원기의 설계자 역할은 유지한다.
- 개발반장이 투입 종료되면 공석으로 두고 후임을 자동 지정하지 않는다. 종료일 당일까지는 유지하고, 종료일이 지난 최초 실행·새로고침 때 지정 해제한다.
- 인력 삭제 또는 종료일 수정으로 현재 투입 자격이 사라지면 개발반장 참조도 해제한다. 개발반장 공석을 이유로 철수·삭제를 막지 않는다. 현장대리인 겸임 시 그 직책의 별도 철수 규칙은 유지한다.
- 그룹 생성·삭제·이동과 개발반장 지정은 서로 독립적이다. 개별 그룹 리더 미지정을 개발반장이 자동 대체하지 않는다.
- 그룹 설정 화면의 전체 그룹 위쪽에 개발반장을 별도로 표시하고, 지정·변경·해제는 팝업으로 처리한다. 공석이면 이름은 기존 원칙대로 빈칸 표시한다.
- 직접 변경은 저장 버튼으로 반영한다. 실행·새로고침 시 투입 종료에 따른 자동 해제는 정상 알림 없이 파일에 자동 반영한다.
- 초기 유원기는 2026-01-01부터 투입, 종료일은 기본값 9999-12-31이다. 이 실제 초기 기간으로 현재 투입 자격을 판단한다.


### 8.2 여러 그룹 구성안과 비교

- 그룹 구성을 1안·2안·3안처럼 여러 개 보관하고 비교한다. 세 개는 예시이며 최대 세 개로 제한하지 않는다. 과거 이력이 아니라 현재 편집 가능한 대안 데이터다.
- 기본 안 이름은 `1안`, `2안`…이며 현재 사용하지 않는 가장 작은 양의 정수를 재사용한다. 직접 이름 변경 가능하며 안 이름은 이 업무 파트 내에서 중복 불가다. 내부 구성안 ID와 표시명을 분리한다.
- 구성안은 새로 만들기·기존 안 복사·이름 변경·삭제를 지원한다. 새 안은 빈 구성, 복사는 해당 안의 인력 그룹·리더·상위 그룹·소속·배치 순서를 복제한다. 그룹 ID 등 구성안 소유 ID는 새로 발급하고 부모·리더 연결은 새 구성안 안으로 다시 연결한다.
- 사람·업체·역할·기술·투입 기간·TBD·현장대리인·연간 목표·개발반장은 공통 원본이다. 안을 복사해도 인력 레코드나 M/M가 늘어나지 않는다. 같은 인력의 정보 수정 및 TBD 확정 전환은 모든 안에 반영되며 그룹 배치만 안별로 유지한다.
- 새 인력·TBD의 그룹 기본값은 모든 안에서 미배정이다. 등록 팝업에서 그룹을 명시적으로 선택하면 적용 중인 안에만 배정하고 다른 안은 미배정으로 유지한다. 일반 인력 상세의 그룹 입력도 적용 중인 안만 편집하며 대상 안 이름을 표시한다. 다른 안의 배치는 그룹 설정에서 편집한다. 인력 삭제·시작 시 TBD 자동 삭제·확정 인력 종료 정리는 숨겨진 안을 포함한 모든 안의 참조에 적용한다. 빈 인력 그룹 및 빈 상위 그룹도 각 안에서 정리하되 구성안 자체는 자동 삭제하지 않는다.
- 한 안의 그룹 이동·리더 변경·상위 그룹 재편·드래그 순서는 다른 안에 영향을 주지 않는다. 같은 사람이 1안에서 Group#1 리더이고 2안에서 Group#2 구성원이어도 허용한다.
- 업무 파트에는 실제 표시 기준인 `적용 중인 안`을 정확히 하나 둔다. 그룹 설정에서 조회·편집하는 안과 적용 중인 안은 구별한다. 조회 안을 바꾸거나 비교만 해서는 적용 안이 바뀌지 않는다.
- `이 안 적용`은 인력 목록의 그룹 열과 다른 화면의 그룹 참조 기준을 이 안으로 바꾼다. 인력·투입 상태·M/M·개발반장·현장대리인은 바꾸지 않는다. 적용 안 표시를 명확히 하고, 파일 반영은 전역 저장 버튼으로 한다.
- 적용 안을 삭제하려면 먼저 다른 안을 적용하도록 안내한다. 마지막 한 안은 삭제하지 않는다. 빈 안은 정상 상태이며 빈 그룹처럼 자동 삭제하지 않는다.
- 비교 화면에서 두 개 이상의 안을 선택하여 나란히 확인한다. 안이 한 개면 비교를 비활성화하고 새 안·복사본 생성을 안내한다. 비교 명단은 종료 인력을 제외한 동일한 공통 인력(현재·예정·TBD)이며 종료 인력 M/M는 기존 실적에 유지한다. 안별 상위 그룹·인력 그룹·리더·구성원·미배정을 표시하고, 그룹 수·배정 인원·미배정 인원·리더 공석 수를 함께 보여준다. 인원 집계는 공통 인력 ID 기준으로 하여 상위·하위 그룹을 중복 합산하지 않는다. 그룹별 M/M는 추가하지 않는다.
- 같은 인력 ID의 안별 소속과 그룹 리더 여부를 비교한다. 표시명이 같은 Group#1이라도 서로 다른 안의 독립 그룹이며 같은 그룹이라고 단정하지 않는다. 인력별 비교에서 각 안의 상위 그룹/인력 그룹 경로와 리더 여부를 보여준다.
- 비교는 조회용이며 편집할 안을 선택하면 그룹 설정의 해당 안으로 돌아간다. 비교 화면에서 인력을 다른 안으로 드래그해 원본 인력이나 소속을 옮기는 기능은 제공하지 않는다.
- 구성안 생성·복사·이름 변경·삭제는 팝업으로 처리한다. 안 선택·비교 상태는 조회 상태, 구성안 내용 및 적용 안 변경은 저장 대상 데이터다. 안 전환 시 이미 적용한 세션 변경을 버리지 않는다. 미적용 팝업 초안은 공통 폐기 확인 규칙을 따른다.
- 초기 데이터에는 빈 `1안` 하나를 만들고 이를 적용 안으로 지정한다. 초기 실제 그룹 배정은 여전히 없다. 기존 단일 그룹 데이터 업그레이드는 기존 배치·리더를 1안으로 옮기며 재실행 때 초기화하지 않는다.

### 8.3 그룹을 묶는 상위 그룹

- 같은 구성안의 여러 인력 그룹을 상위 그룹으로 묶고 이름을 직접 지정할 수 있다. 상위 그룹에 속하지 않는 인력 그룹도 허용한다.
- 인력 그룹은 해당 안에서 최대 한 상위 그룹에 속한다. 서로 다른 안의 그룹을 연결하거나, 같은 그룹을 여러 상위 그룹에 중복 배정하지 않는다.
- 인력은 인력 그룹에만 직접 배정한다. 상위 그룹의 구성원 목록과 인원은 하위 그룹에서 파생하며 상위 그룹에 같은 인력을 별도 복제하지 않는다. 한 사람의 여러 그룹 소속 금지 규칙을 우회하지 않는다.
- 상위 그룹의 추가·이름 변경·하위 그룹 선택·묶음 해제·삭제는 팝업으로 처리한다. 상위 그룹과 하위 그룹 순서 및 상위 그룹 간 인력 그룹 이동은 드래그로 조정하고 구성안별로 저장한다.
- 상위 그룹을 삭제하거나 묶음을 해제하면 하위 인력 그룹·구성원·그룹 리더는 유지한다. 하위 그룹은 상위 그룹 없는 상태로 돌아가며 인력 미배정으로 바뀌지 않는다.
- 상위 그룹은 하위 인력 그룹이 최소 하나 있어야 한다. 마지막 하위 그룹이 삭제·이동해 비면 상위 그룹도 자동 삭제한다. 인력 그룹이 비어서 삭제되면 이 정리를 연쇄 적용한다. 구성안은 유지한다.
- 상위 그룹에서도 M/M 집계는 제공하지 않는다. 업무 파트 전체 개발반장은 모든 상위·하위 그룹의 총괄이라는 기존 범위를 유지한다.
- 첫 버전은 상위 그룹 → 인력 그룹 → 인력 구조로 제한한다. 상위 그룹 안에 다른 상위 그룹을 넣는 반복 중첩은 지원하지 않는다.
- 상위 그룹에는 별도의 선택 리더를 둘 수 있고 공석(null)을 허용한다. 선택 범위는 해당 상위 그룹의 하위 인력 그룹에 소속된 인력이며 TBD도 가능하다. 개별 인력 그룹의 리더일 필요는 없고, 선택했다고 인력의 직접 소속 그룹을 바꾸지 않는다.
- 상위 그룹 리더는 구성안별 지정이며, 인력 그룹 리더·업무 파트 전체 개발반장과 구별한다. 겸임 가능하되 각 직책의 자격 규칙을 충족해야 한다.
- 하위 그룹·인력의 이동·삭제·투입 종료로 상위 그룹 리더가 그 하위 구성원이 아니게 되면 상위 그룹 리더도 해제하고 공석 처리한다. 자동 승계하지 않는다. 같은 상위 그룹 안의 하위 그룹 간 이동이면 지정 유지한다. 모든 안에 동일하게 적용한다.

## 9. 현장대리인

### 9.1 업체별 지정과 복수 선임

- AGS·BP 업체에 현장대리인을 지정한다. 정직원 업체에는 적용하지 않는다. 지정은 업체 ID와 인력 ID로 연결하고 삭제된 인력 참조는 제거한다.
- 같은 업체라도 기존 현장대리인과 업무 역할 또는 기술 구분이 다르면 추가 현장대리인을 선임할 수 있다. 업체 전체 한 명 제한은 적용하지 않는다.
- 업무 역할은 설계자·개발자 등의 역할 값, 기술 구분은 F/E·B/E·F/S 등의 기술 값이다. 추가 선임은 기존 인력을 교체하는 동작과 구별해 화면에서 제공한다. 추가 선임으로 유효한 기존 현장대리인 지정을 해제하지 않는다.
- 예: 다솜에스엔씨의 범미(설계자·F/E)를 유지하면서 같은 업체의 다른 설계자·B/E 인력을 추가 선임할 수 있다. 이 예시는 새 인력 등록 지시가 아니므로 초기 명단에 임의 인력을 생성하지 않는다.
- 현장대리인 지정 단위는 (업체 ID, 역할 ID, 기술 ID)의 정확한 조합이며 조합별 최대 한 명이다. 같은 업체라도 역할 또는 기술 중 하나 이상이 다르면 추가 선임할 수 있다. 동일 조합의 후임 지정은 교체로 처리한다.
- F/S·B/E·F/E는 현장대리인 분류에서는 서로 독립된 값이다. F/S가 양쪽 기술 수행 가능이라는 의미여도 B/E·F/E 담당을 자동 대체하거나 중복 조합으로 판정하지 않는다. 같은 업체의 같은 역할에서 F/S·B/E·F/E 현장대리인을 각각 한 명씩 둘 수 있다.
- TBD는 AGS·BP 업체, 업무 역할, 기술 구분이 모두 지정되어 있어야 현장대리인으로 선임할 수 있다. 역할 또는 기술 중 하나라도 비어 있으면 최초·신규·추가 선임 모두 불가하며 선임 후보에서 제외한다. 대표가 없는 업체의 첫 선임에도 예외를 두지 않는다.
- 일반 TBD 등록·그룹 구성·그룹 리더 지정에서는 역할·기술을 선택 입력으로 유지한다. 현장대리인 선임 자격을 TBD 등록 필수값으로 확대하지 않는다.
- 현장대리인인 TBD의 역할·기술을 비우려면 대표 지정을 함께 해제·인계해야 한다. 분류가 빈 상태로 대표 지정을 유지하지 못하게 검증하고, 해당 원 작업의 인계·취소·수동 저장 규칙을 따른다.
- 현장대리인은 모든 그룹 구성안에서 공통이다. 안 복사·비교·적용으로 별도 현장대리인을 생성하지 않는다. 파일 스키마에서 업체당 단일 인력 ID만 저장하지 말고 복수 지정이 가능해야 한다.
- 위 업체·역할·기술 자격을 충족하는 TBD와 확정 예정 인력도 현장대리인으로 지정할 수 있다. 같은 업체의 유효한 인력으로 확정 전환하면 지정은 유지한다. 후보가 없으면 공석을 허용한다.
- 복수 현장대리인 중 한 명의 철수·삭제·역할 또는 기술 분류 변경 시, 동일 업체에 다른 유효한 현장대리인이 있으면 역할·기술과 무관하게 그 대표에게 일괄 인계한다. 같은 분류의 새 대표를 별도 선임할 필요는 없다.
- 변경 대상자를 제외한 동일 업체의 유효한 인계 대상 현장대리인이 한 명이면 그 사람에게 자동 인계한다. 두 명 이상이면 Focal이 팝업에서 인계받을 한 명을 선택한다. 후보의 이름·역할·기술을 표시하며 임의로 한 명을 자동 선택하지 않는다. 실제 철수에서는 현재 투입 중인 대표만 인계 후보로 표시한다.
- 인계 대상 선택을 취소하면 진행 중인 철수·삭제·분류 변경도 반영하지 않는다. 실행·새로고침 자동 처리에서도 후보가 두 명 이상이면 사용자 선택이 필요한 예외로 처리하며 선택을 완료하기 전 관련 변경을 파일에 저장하지 않는다. 여러 후보 중 선택하지 않은 현장대리인의 지정은 유지한다.
- 일괄 인계는 변경 대상자의 현장대리인 지정을 해제하고 기존 다른 대표가 관리하도록 처리한다. 다른 대표의 역할·기술이나 다른 인력의 분류를 바꾸지 않으며 같은 인력을 중복 대표로 생성하지 않는다. 다른 대표의 기존 지정도 유지한다.
- 분류 변경에서는 대상자의 인력·그룹 소속을 유지하고 대표 직책만 인계·해제한 뒤 새 분류를 적용한다. 다른 대표가 없다면 유효한 새 조합으로 지정을 유지한다.

### 9.2 최초 실제 투입과 미접속 후 지정

- 현재 투입 인력이 없던 업체에 최초 실제 투입이 발생하면 대표를 지정한다. 한 명이면 자동 지정하고 같은 날 여러 명이면 Focal이 선택한다. 선택한 인력과 동일한 업체·역할·기술 조합의 예정·TBD 대표는 실제 투입자로 교체하되, 다른 조합의 유효한 예정·TBD 대표는 유지한다.
- 앱을 장기간 열지 않아 여러 시작일의 인력이 이미 투입되어 있으나 유효한 현재 현장대리인이 없는 경우, 현재 투입자 중 가장 이른 시작일을 우선한다. 최선순위 날짜가 같은 후보가 여러 명이면 Focal이 선택한다.
- 기존 현재 투입 중인 현장대리인을 자동으로 덮어쓰지 않는다. 새 역할·기술의 인력이 들어왔다고 추가 현장대리인을 자동 생성하지는 않으며, 추가 선임은 Focal이 수행한다.
- 실행·새로고침 및 인력 적용 시 평가하되 앱이 열린 채로 날짜가 지났다는 이유만으로 파일을 자동 변경하지 않는다.
- 사용자 선택이 필요한 경우는 정상 결과 알림 생략 원칙의 예외다. 일괄 인계한 뒤 이전 역할·기술 조합의 공석을 이유로 대표를 자동 추가 선임하지 않는다.

### 9.3 철수 전 인계

- 현재 투입 중 현장대리인의 유한한 종료일 입력·변경 시, 동일 업체의 다른 현재 투입 중 현장대리인이 있으면 그 사람에게 일괄 인계하고 종료일 변경을 허용한다. 미래 종료일을 미리 입력하는 경우도 입력 시점에 평가한다. 역할·기술이 다른 대표에게도 인계한다.
- 실제 철수 후임은 동일 업체의 현재 투입 중인 확정 인력만 가능하다. 예정·TBD를 실제 철수 후임으로 선택해 이 조건을 우회하지 않는다.
- 인계 가능한 다른 대표가 없으나 동일 업체의 다른 현재 투입 인력이 있으면 후임부터 지정한다. 차단 문구는 정확히 `현장대리인 변경 선 처리 후 철수 가능`이다.
- 동일 업체의 다른 현재 투입 인력이 전혀 없으면 후임 없이 철수할 수 있다. 남은 예정·TBD 대표는 유지하고 철수 대상자의 지정만 해제한다. 예정·TBD만 남는 경우도 마지막 현재 투입 인력 예외다.
- 예정·TBD의 계획 종료일 편집에는 실제 철수 차단을 적용하지 않고 최소 15일 등 계획 기간 검증만 적용한다. 신규 등록의 기본 종료일 9999-12-31 자동 적용도 철수 입력이 아니다.
- 종료일 검사는 미정에서 유한일 지정 및 유한일의 앞당김·연장에 적용한다. 기존 종료일 유지 또는 종료 미정으로 되돌림 자체에는 새 철수 인계를 요구하지 않는다.
- 인계와 종료일 변경은 같은 팝업 적용 작업으로 처리한다. 팝업 취소·검증 실패 시 인계도 반영하지 않으며 파일 반영은 전역 저장으로 한다.

### 9.4 삭제 및 업체 변경

- TBD·예정 취소 및 오등록 삭제는 철수 차단과 구분한다. 현장대리인 삭제 시 같은 업체의 다른 유효한 현장대리인에게 우선 일괄 인계한다. 역할·기술이 달라도 허용하며, 이미 지정된 예정·TBD 대표도 유지할 수 있다. 실제 철수 후임 자격과 구분한다.
- 다른 현장대리인이 없을 때만 새 승계 후보를 평가한다. 동일 업체의 남은 확정 인력 중 현재 투입 중 → 투입 예정 순, 같은 상태는 시작일 빠른 순 → 먼저 등록한 순이다. TBD·종료 인력은 새 후보에서 제외한다. 후보의 역할·기술이 같아야 한다는 제한은 추가하지 않는다.
- 후보가 없으면 지정 해제 후 삭제를 허용한다. TBD만 남는 경우도 공석 허용이며 삭제 자체를 막지 않는다.
- 사용자 삭제로 인계·승계되면 `(업체명)의 현장대리인이 (이름)으로 변경 됨` 알림을 표시한다. 시작 시 자동 TBD 삭제에도 같은 참조 정리 원칙을 적용하되 정상 승계·그룹 리더 알림은 생략한다.
- 대표인 예정·TBD의 업체 변경 또는 다른 업체로 확정 전환 시 기존 업체 지정을 해제한다. 기존 다른 대표 우선 인계 → 없을 때 새 후보 평가 순으로 처리한다. 새 업체의 기존 대표를 유지하며 직책을 새 업체로 자동 이월하지 않는다. 실제 최초 투입이면 9.2절을 평가한다.
- 그룹 리더·상위 그룹 리더·개발반장·현장대리인은 별개 직책이다. 인력 삭제 시 관련 참조를 함께 정리한다.

## 10. 화면과 정렬

### 10.1 인력 목록

- 그룹으로 묶지 않고 전체 인력을 하나의 표로 표시한다.
- 기본 열: 이름·상태·직원 타입·업체·역할·기술 구분·그룹·투입 시작일·투입 종료 예정일. 그룹 열은 적용 중인 안의 인력 그룹 소속을 표시한다. 그룹 설정에서 다른 안을 미리 보는 것만으로 목록의 소속을 바꾸지 않는다.
- 인력별 연간 M/M 열과 별도 인력별 M/M 화면은 제공하지 않는다.
- 가사번·DOSS ID·IP·좌석번호·메모는 인력 상세에서만 조회·수정한다. 좌석번호를 목록에 노출하지 않는다.
- 기본 목록은 투입 중·투입 예정·TBD. 종료 인력은 `종료 인력 포함` 옵션으로 조회한다.
- 검색 기능은 첫 버전에서 제외한다. 추가 복합 필터는 구현 확정 범위로 넣지 않는다.
- 열 헤더 클릭으로 전체 목록을 오름차순·내림차순 정렬하고 방향을 표시한다.
- 기본 순서 복귀 기능을 둔다. 표 정렬로 그룹 설정의 저장 배치를 변경하지 않는다.

기본 정렬은 다음 우선순위를 연속 적용한다.

| 우선순위 | 순서 |
| --- | --- |
| 1 상태 | 투입 중 → 투입 예정 → TBD → 종료 |
| 2 직원 타입 | 정직원 → BP → AGS → 미정(null) |
| 3 역할 | 설계자 → 개발자 → 신규 역할 가나다순 → 미정(null) |
| 4 기술 | F/S → B/E → F/E → 신규 기술 가나다순 → 미정(null) |
| 5 시작일 | 빠른 날짜부터 |
| 6 종료일 | 빠른 날짜부터. 내부값 9999-12-31은 마지막 |
| 7 이름 | 가나다순 |

기본 순서에서는 현재 표시 대상 중 역할이 Focal인 정직원을 목록 최상단에 우선 표시한다. 종료 인력 숨김 옵션으로 제외된 Focal을 다시 노출하지 않는다. Focal이 여러 명이면 이름 가나다순이다. 역할이 비어 있는 정직원은 같은 상태·타입·빈 역할 범위에서 날짜·기술보다 이름 가나다순을 우선한다. 빈 역할·기술을 하이픈으로 보충하지 않는다. 나머지는 위 다단 정렬을 적용한다. 헤더 정렬은 조회용 임시 정렬이며 Focal 고정 우선보다 클릭한 열의 정렬을 우선한다. 기본 순서 복귀 시 위 규칙을 복원한다. 날짜는 실제 날짜, 상태·타입·역할·기술은 위 정의 순서, 일반 문자열은 한국어 기준으로 비교한다. 미정 종료일과 null은 화면에서 비어 있어도 별도 내부값으로 비교하며, 일반 헤더 정렬의 빈값은 오름·내림 모두 뒤로 둔다. 동일 값이면 이름 → 내부 등록 순서로 안정 정렬한다.

### 10.2 화면과 팝업 원칙

- PC에서 Focal이 연간 목표·부족 M/M를 확인하고 인력을 바로 관리하기 좋은 레이아웃을 설계자가 구성한다. 불필요한 화면 이동을 최소화한다.
- 주 메뉴는 연간 현황 / 인력 관리 / 그룹 설정 / 기본 설정이다. 그룹별 보기는 그룹 설정에서만 제공한다.
- 인력 목록의 행을 클릭하면 목록 위 팝업을 연다. 별도 수정 페이지나 오른쪽 상세 패널 방식은 사용하지 않는다.
- 인력 팝업에 기본 정보와 추가 정보 전체를 함께 노출하고 그 안에서 수정한다. 좌석번호·메모·가사번·ID·세 IP를 보기 위해 별도 화면으로 이동하지 않는다.
- 인력 등록·TBD 등록 및 확정 전환도 같은 팝업 패턴을 사용한다. 상황별 필수값과 입력 잠금만 다르게 적용한다.
- 목표 설정·그룹 생성·이름 변경·리더 지정·프로젝트/파트 기본 설정 등 팝업으로 완료 가능한 작업은 팝업으로 처리한다.
- 연간 목표·실적은 연도 선택 기준으로 조회한다. 월별 표·그룹별 M/M·인력별 M/M는 제외한다.

### 10.3 공통 배치와 버튼

- 화면 간 콘텐츠 여백·제목 위치·버튼 높이·간격·정렬을 통일한다.
- 현재 Figma 기준 버튼 높이 40px, 같은 동작 묶음의 버튼 사이 12px, 입력·카드와 팝업 안쪽 여백은 일관된 8px 계열 기준으로 구성한다.
- 화면 상단 오른쪽에는 파일 저장 버튼과 저장 상태를 공통 배치한다. 파일 경로 등 구현 정보는 일반 화면에 노출하지 않는다.
- 팝업은 왼쪽 메뉴바를 제외한 작업 영역의 가로 중앙에 정렬한다. 전체 브라우저 너비의 중앙에 맞추지 않는다. 메뉴 너비가 바뀌면 작업 영역 중심도 함께 재계산하며 좁은 화면에서는 작업 영역 안에 여백을 두고 크기를 제한한다.
- 팝업은 제목·우측 닫기·본문·하단 동작 영역 구조다. 하단 오른쪽에 취소·적용, 삭제가 있는 경우 하단 왼쪽에 둔다.
- 팝업의 적용은 앱 내 편집 결과 반영이며 JSON 파일 저장과 구분한다. 적용 후 실제 진입 화면 또는 상위 팝업으로 돌아와 미저장 표시를 유지하고 전역 저장 버튼으로 파일에 반영한다.
- 팝업은 연간 현황·인력 관리·그룹 설정 등 실제 진입 화면으로 복귀한다. 그룹 팝업은 열었던 구성안 ID와 그룹 ID를 유지해 다른 안·그룹에 잘못 적용하지 않는다. 조회 연도·헤더 정렬·종료 인력 표시·스크롤을 유지한다. 인력 팝업의 적용 후에도 고정된 인력 목록으로 이동하지 않고 원래 진입 화면으로 돌아간다.
- 미적용 수정이 있는 상태에서 취소·닫기·Esc로 닫으면 `변경 내용을 버리시겠습니까?` 확인을 표시한다. 버리면 팝업 초안만 폐기하고, 취소하면 팝업에 남는다. 이미 적용한 세션 변경은 유지한다. 팝업 바깥 클릭으로는 닫지 않는다.
- 수정이 없는 상태에서 취소·닫기·Esc는 추가 확인 없이 닫는다. 적용 후에는 변경 폐기 확인을 표시하지 않는다.
- 미적용 상위 초안에 종속된 인계·삭제 확인은 상위 작업과 한 변경으로 취급한다. 상위 취소 시 관련 인계·삭제도 취소한다. 별도로 완료한 기본값·목표 수정은 세션 변경으로 유지한다.
- 하위 팝업에서 돌아오면 상위 팝업의 초안과 스크롤을 보존한다. 하위에서 변경한 업체·목표 등은 상위의 유효성 검사와 집계에 즉시 반영하되 편집 중인 다른 입력을 초기화하지 않는다. 필요 인원 계산에서 목표 설정 후에는 필요 인원 계산 팝업으로 복귀해 재계산한다.
- 긴 입력 내용은 팝업 본문 내부에서 스크롤하고 제목과 하단 동작은 확인 가능하게 구성한다.
- 글꼴은 Figma에서 Noto Sans KR로 검토했으나 실제 폐쇄망 앱은 시스템 한글 글꼴을 우선해 외부 폰트 다운로드와 대용량 폰트 포함을 피한다.

### 10.5 기본 설정

- 전체 기본값을 관리하는 기본 설정 메뉴를 둔다. 프로젝트명·업무 파트명·업체·역할·기술 구분 등을 등록·수정한다.
- 신규 업체·역할·기술 값 추가, 이름 수정, 사용 안 함 전환을 제공한다. 프로젝트·업무 파트는 이 데이터 묶음의 이름을 수정하는 대상이며 여러 프로젝트·파트 전환이나 현재 프로젝트의 비활성화 기능을 추가하지 않는다. 설정 항목 편집은 팝업으로 처리한다.
- 인력 투입·수정 팝업에서는 설정된 값을 콤보박스로 선택한다. 값을 소스 코드에 하드코딩하지 않는다.
- 업체 등록 시 직원 타입을 함께 지정한다. 인력(TBD·예정·투입 중·종료 포함)이 참조하는 업체의 타입 매핑 변경은 금지한다. 업체명 수정은 허용하고 내부 ID 연결을 유지한다. 인력의 업체 변경 잠금은 업체 ID 연결 변경에 대한 제한이며 업체 마스터의 이름 수정과 구별한다. 참조 인력이 전혀 없는 업체만 타입 매핑 변경 가능하다.
- 초기 매핑은 SKAX→정직원, 애커튼테크놀로지→AGS, 현재 네 협력업체→BP다.
- 업체를 선택하면 연결된 직원 타입을 자동 결정한다. 인력 등록·수정·TBD 등록·확정 전환에서 직원 타입 선택/입력란을 제공하지 않는다. 목록의 타입 열은 자동 결정된 값을 조회 용도로 유지한다.
- 업체 미정 TBD는 직원 타입도 null이다. 기본 설정에서 업체의 타입을 매핑하는 동작은 유지한다.
- 확정 인력의 직원 타입 잠금과 업체 변경 가능 시점은 유지한다. 투입 전 업체 변경도 기존 타입과 같은 타입의 업체 중에서만 허용한다.
- 사용 중인 설정값을 지워 연결을 끊지 않는다. 사용 안 함으로 바꾸면 기존 인력의 표시·연결은 유지하고 신규 선택 목록에서만 숨긴다. 기존 항목 편집 시 사용 안 함인 현재 값도 보여주며 다른 값으로 강제 치환하지 않는다.
- 설정값은 내부 ID와 표시명을 분리한다. Focal 등 기능상 의미는 표시명 변경으로 사라지지 않게 식별한다.
- 직원 타입 정직원·BP·AGS는 고정된 분류이며 새 타입 추가 기능은 없다. 업체·역할·기술의 마스터 값 추가와 구별한다.
- 설계자·개발자는 초기 역할이며 고정 enum이 아니다. 기본 설정에서 추가한 활성 역할도 BP·AGS 확정 인력의 필수 역할 값으로 선택할 수 있다. Focal은 정직원 전용 기능 역할로 유지한다. 신규 역할은 기본 정렬에서 설계자 → 개발자 뒤에 표시명 가나다순으로 배치한다.
- 역할·기술이 비어 있는 TBD는 목록과 상세에 빈칸으로 표시하며, 인력 확정 전환 시 AGS·BP 역할·기술 필수값을 입력해야 한다.
- 신규 기술 값도 콤보에서 선택할 수 있으며 기본 F/S·B/E·F/E 뒤 가나다순으로 정렬한다. 역할·기술 이름 변경은 내부 ID의 기능 의미와 기본 정렬 우선순위를 바꾸지 않는다.
- 기본값 추가·수정·비활성화도 일반 수동 저장 원칙을 적용한다. 적용 시 세션의 콤보 목록에는 즉시 반영하되 파일 반영은 전역 저장 버튼으로 한다.

## 11. 초기 데이터

초기 프로젝트·업체·인력·TBD·개발반장 지정은 새 데이터 생성 시 한 번만 제공한다. 초기화 완료 여부는 스키마/초기화 표식으로 기록한다. 재실행·새로고침·앱 버전 갱신 시 누락된 초기 인력을 다시 넣지 않는다. 사용자가 삭제·수정한 값과 공석·빈 그룹 상태를 유지한다. 기존 데이터의 빈 배열을 새 데이터로 오인하지 않는다. 데이터 오류를 초기화로 복구하지 않는다.

NOVA / Service Order(무선) 사용자용 초기 데이터다. 다른 Focal에게 강제로 넣는 공통 명단이 아니다. 정직원은 장은실 한 명, AGS는 현재 없고 BP는 아래 13명이다. 확정 인력은 총 14명이며 그중 12명은 현재 투입, 2명은 투입 예정이다(2026-10-17 기준).

## 12. 구현 검증 기준

1. VDI의 두 브라우저에서 인터넷·서버·런타임 설치 없이 실행한다.
2. 최초 앱 폴더 연결·기억한 연결 재사용·JSON 직접 저장·재실행 복원·연결 단절·실패·취소 처리를 확인한다. 백업 기능은 구현하지 않는다.
3. 일반 수정은 수동 저장, 시작 시 자동 처리는 변경분 자동 저장으로 구분한다.
4. 미저장 작업을 버리는 동작의 세 선택, 팝업 적용과 파일 저장의 분리 및 저장 실패 시 현재 작업 유지가 동작한다.
5. 가사번·ID 접두어와 앞자리 0, IPv4 각 칸·Tab·범위, 숫자 8자리 날짜 입력을 검증한다.
6. null과 미정 종료일을 빈칸으로 표시하고 필수값·15일 규칙·실제 조기 철수 예외를 검증한다.
7. M/M 예제·윤년·연도 경계·중간 무반올림과 인력별 연간 반올림 후 합산·전체와 타입별 일치·TBD 제외를 검증한다. 인력별 M/M는 화면에 노출하지 않는다.
8. 목표 미설정과 0 입력을 구분한다.
9. TBD 날짜 조정은 오늘 경계·14/15일·연말 이월을 확인하고, 잔여 14일 삭제·15일 유지를 확인한다.
10. TBD 확정 시 ID·그룹·리더 유지 및 중복 집계 방지를 확인한다.
11. 그룹 생성·이동·리더 미지정·직접 삭제·마지막 구성원 자동 삭제를 확인한다.
12. 현장대리인 최초 지정·동일일 선택·철수 차단·마지막 인력 예외·삭제 승계 순서와 정확한 문구를 확인한다.
13. 추가 정보 중복 경고 및 추가 정보 중복 판정을 위한 기간 비교 검사가 없음을 확인한다. 인력 투입 기간의 15일 규칙·날짜 비교는 유지한다. 인력 타입 직접 입력란 제거·업체별 자동 산출·업체 미정 null, 확정 인력 타입 변경 잠금, 신규 예정·TBD의 내일 이후 시작일 제한을 확인한다.
14. 기본 목록 범위·다단 정렬·헤더 정렬과 그룹 설정의 독립성을 확인한다.
15. 실제 앱 파일 크기를 확인하고 경량화 목표 달성 여부를 기록한다.
16. 종료 인력의 그룹 자동 해제·빈 그룹 삭제·인력 기록 보존을 확인한다.
17. 삭제 번호 재사용, 그룹명·TBD 표시명 중복 금지, 장은실/Focal 구분과 최상단 표시를 확인한다.
18. 저장 버전 충돌 시 중단, 손상 파일 보존, 자동 저장 실패 시 진입 차단·재시도를 검증한다.
19. 행 클릭 팝업에 모든 추가 정보가 노출되고 버튼 배치·높이·간격이 화면 간 일관됨을 확인한다.
20. 개발반장 초기 유원기 참조, 현재 투입 중 인력만 선택, 그룹 소속과 독립, 지정 변경·해제, 종료 후 공석 및 자동 승계 없음을 검증한다.
21. 신규 예정 등록의 내일 이후 제한과 TBD 확정 전환의 오늘·과거 허용을 구분한다. 전환 결과가 종료면 그룹·리더 참조도 함께 정리한다.
22. 사용 중인 업체의 타입 매핑 변경 차단, 이름 변경 시 ID 유지, 추가 역할·기술의 콤보 선택·정렬을 확인한다.
23. 팝업 원래 진입 화면·상위 팝업 복귀, 연도·정렬·스크롤 유지, 미적용 초안 폐기 확인 및 세션 변경 보존을 검증한다.
24. 초기 생성은 한 번만 수행하며 재실행·새 버전 실행 시 삭제한 초기 인력·TBD·그룹·개발반장을 복원하지 않는지 확인한다.
25. 연간 그래프의 확정·TBD 분리·동적 축·목표 미설정 및 0 목표를 확인한다. 필요 인원은 정확한 올림과 0 부족분 우선 처리, 확인 후 개별 TBD 생성 및 수동 저장을 검증한다.
26. 일정 14/30일 범위·투입/철수 각각 집계·중첩 팝업 복귀, Phase 최상단 표시·참고 일정 표기·M/M 및 인력 일정과 독립성을 확인한다.
27. 시작 시 자동 TBD 삭제에서는 그룹 리더 알림과 현장대리인 승계 알림이 모두 없고, 수동 삭제에서는 정해진 알림이 표시되는지 확인한다.

28. 구성안 생성·복사·독립 편집·비교·적용·삭제 및 마지막 한 안 보존을 확인한다. 복사 시 인력/M/M 중복 생성이 없어야 한다.
29. 적용 안과 조회 안 분리, 인력 목록의 적용 안 소속 표시, 전역 저장 전후 상태와 모든 안의 인력 삭제·종료 참조 정리를 확인한다.
30. 상위 그룹 묶기·이동·해제·삭제 시 하위 인력 그룹과 인력을 보존하고, 비어 있는 상위 그룹만 정리하며 인원 중복 집계가 없는지 확인한다. 중첩 및 상위 리더 정책은 확정 규칙에 맞춰 하위 구성원 선택·공석·이동에 따른 리더 해제를 검증한다.

31. 업체·역할·기술의 정확한 조합별 최대 한 명을 검증한다. 같은 역할의 F/S·B/E·F/E 현장대리인은 각각 독립 선임 가능해야 한다. 복수 현장대리인 추가 선임 시 기존 다른 역할·기술 대표를 보존하고, 초기 범미 지정과 실제 인력 원본을 임의 변경하지 않는지 확인한다. TBD의 역할 또는 기술이 비면 신규·추가 선임 모두 차단하고, 두 값이 있어도 업체 미정이면 차단하는지 확인한다. 일반 TBD 등록·그룹·리더 자격에는 이 조건을 확대하지 않는다.

32. 복수 대표의 철수·삭제·분류 변경 시 다른 기존 대표에게 역할·기술과 무관하게 일괄 인계하고, 다른 대표가 없으면 기존 후임·승계 규칙을 적용하는지 검증한다. 인계로 인력 분류·M/M·그룹 소속을 바꾸거나 대표를 중복 생성하지 않는다.

33. 유효한 기존 인계 대상이 한 명이면 자동 인계, 두 명 이상이면 Focal 선택 팝업을 검증한다. 선택 취소 시 원 작업과 파일을 유지하고, 시작 시 자동 처리에서도 선택 완료 전 저장하지 않는지 확인한다.

34. 최초 투입자의 자동 대표 지정이 다른 역할·기술의 유효한 대표를 지우지 않는지 확인한다. 일괄 정리 대상 인력을 인계 후보로 고르지 않아야 한다.
35. 등록 팝업의 명시적 그룹 선택은 적용 안에만 반영하며 다른 안은 미배정임을 확인한다. 그룹 수정·상위 그룹 설정 팝업의 안 ID·그룹 ID 및 취소 후 복귀를 검증한다.
36. 최초 빈 1안에서는 비교·상위 그룹 생성 조건을 안내하고, 구성안 적용과 비교 대상 선택이 별개 흐름인지 확인한다. 인력 행별 상세·삭제 이름이 해당 레코드와 일치하고 IP 네 번째 칸과 메모가 잘리지 않아야 한다.

## 13. 남은 데이터와 구현 확인 사항

주요 기능 규칙은 합의했다. 이미 결정한 내용을 다시 질문하지 말고 구현을 막는 충돌만 확인한다.

### 13.1 나중에 입력 가능한 실제 데이터

- 2026년 외 연도의 목표 M/M, 초기 그룹과 리더 배정. 2026년 목표는 65.000 M/M로 확정했으며 전체 확정 인력 14명의 시작일은 11.1절에서 확정했다.
- 가사번·DOSS ID·IP·좌석번호·메모 등 선택 정보.
- 과거 투입 데이터에 임의의 날짜를 넣어 실적을 확정하지 않는다.

### 13.2 구현 시 정리할 사항

- JSON 파일명·스키마 버전·기존 데이터 마이그레이션 세부사항. 백업 파일명은 불필요하다.
- 실제 VDI의 브라우저에서 로컬 HTML 폴더 선택·연결 기억·재실행 권한 동작 검증. VDI 폴더 자체에 별도 권한 신청은 불필요하다.
- 동시 버전 비교는 완전한 동시 쓰기 잠금이 아니라는 한계를 유지한다.
- Sub_Component 할당은 의도적으로 후속 범위다.
- 최소 지원 PC 화면 크기와 브라우저 배율을 실제 VDI에서 확인한다. Phase 표는 본문 첫 위치를 유지하되 모든 창 크기에서 전체 표의 무스크롤 노출을 보장하는 것으로 해석하지 않는다.

### 13.3 기능 정책 확정 상태

- 사용자의 추가 선택이 필요한 기능 정책 미결사항은 이번 점검에서 확인되지 않았다. 구현·실환경 검증을 완료했다는 의미는 아니다.
- 역할·기술 미정 TBD는 최초·신규·추가 현장대리인 선임 모두 불가로 확정했다.
- 복수 대표의 철수·삭제·분류 변경 시 다른 유효한 기존 대표에게 일괄 인계하며, 대상 한 명이면 자동 인계하고 두 명 이상이면 Focal이 한 명을 선택한다.
- VDI 파일 접근·권한 유지·저장 검증은 13.2절의 구현 검증 사항이며 기능 정책 미결과 구별한다.
- Phase 원본 일정의 최신성은 별도 확인이 필요하다. 확인 전까지 참고 일정으로 표시한다. Sub_Component 상세 업무 배정은 후속 범위다.

## 14. Codex 인계

현재 합의된 기능을 구현한다. 첫 버전에서는 월별 표·그룹별 M/M·전체 인력 목록의 그룹 묶기·역할로 제한하는 그룹 리더·서버형 구조·일반 자동 저장·백업·추가 정보 중복 검사·인력별 연간 M/M 표시를 제외한다. 인력 초기값을 추측하지 않고 미정 항목 중 구현을 막는 내용만 확인한다. 개발 환경에서 빌드 도구를 쓰더라도 최종 사용자는 설치 없이 폐쇄망에서 완성된 HTML을 실행할 수 있어야 한다. 실제 파일 API 검증을 우선하고 자동 처리와 사용자 수동 저장의 경계를 지킨다.

### 14.1 플로우 검수 기준

- Figma와 구현에서 인력 등록·TBD 추가·TBD 확정 전환·개발반장 지정·업체 추가·기본 설정 편집·삭제 확인에 진입과 복귀 경로를 제공한다. 주요 동작에 연결되지 않은 버튼을 완료된 흐름으로 취급하지 않는다.
- 모든 인력 행은 해당 레코드의 상세를 연다. 특정 예시 인력 상세를 공통으로 열지 않는다. 시안의 공통 예시 화면은 실행 앱의 레코드 바인딩을 대신하지 않는다.
- 등록·편집·전환 적용은 세션 변경, 상단 저장은 파일 반영이라는 경계를 유지한다. Figma의 화면 이동은 실제 데이터 저장·검증 기능을 의미하지 않는다.
- 초기 데이터는 1회만 생성하고, 삭제한 초기 인력·TBD·그룹·개발반장을 재실행 시 복구하지 않는다.
- 현재 본문을 단일 구현 기준으로 사용한다. 디자인 예시·과거 대화에서 별도 규칙을 추출하지 않는다.
### 14.2 데이터 소유 범위와 참조 원칙

| 데이터 | 소유 범위 | 연결 및 불변 조건 |
| --- | --- | --- |
| 인력·TBD | 업무 파트 공통 | 한 투입당 ID 한 개. 역할·기술·업체 ID·기간·추가 정보는 공통 원본 |
| 업체·역할·기술 마스터 | 업무 파트 공통 | 표시명과 ID 분리. 이름 변경으로 분류 의미·연결이 달라지지 않음 |
| 구성안 | 업무 파트 | 인력 ID를 참조하며 인력 원본을 복제하지 않음. 적용 안 ID는 정확히 하나 |
| 인력 그룹·상위 그룹·리더 | 특정 구성안 | 그룹과 부모의 구성안 ID 일치. 인력 직접 소속은 안마다 최대 한 인력 그룹 |
| 개발반장·현장대리인 | 업무 파트 공통 | 구성안과 독립. 같은 인력 ID를 연결하고 안 복사 시 복제하지 않음 |
| 연도별 목표 | 업무 파트·연도 | 전체 목표 한 개. M/M 집계는 저장된 그룹 구조와 독립적으로 계산 |

- 공통 인력 레코드에 구성안과 무관한 단일 그룹 ID를 두어 모든 안의 배치를 덮어쓰지 않는다.
- 인력 삭제·종료·전환은 영향을 받는 모든 안의 인력 그룹·그룹 리더·상위 리더와 공통 직책 참조를 같은 적용 작업에서 정리한다.
- 빈 인력 그룹 → 빈 상위 그룹 순으로 정리하되 구성안을 자동 삭제하지 않는다. 정상적인 빈 적용 안을 오류로 취급하지 않는다.
- 그룹 생성·구성안 적용·현장대리인 선임·인계의 확인 팝업은 해당 작업 초안과 함께 검증하고, 일부 참조만 갱신된 상태로 저장하지 않는다.

### 14.3 사용자 흐름과 조건별 완료 기준

| 시작 위치·조건 | 처리 흐름 | 완료 기준 |
| --- | --- | --- |
| 최초 연결·재실행 | 연결/권한 확인 → 정리·필요 선택 → 변경분 저장 → 메인 | 완료 전 편집 화면 미노출. 실패 시 원본 유지·재시도, 초기화 버튼 없음 |
| 처음 그룹 설정 진입 | 빈 1안 → 구성원 선택 → 리더 지정 → 적용 | 실제 초기 배정은 빈 상태. 모든 인력이 자동으로 예시 그룹에 들어가지 않음 |
| 다른 구성안 검토 | 안 선택·배치 편집 → 두 개 이상 선택 → 비교 | 조회 안·적용 안 구분, 동일 인력의 소속·리더·미배정 비교 |
| 실제 사용 안 변경 | 이 안 적용 → 영향 확인 → 적용 | 인력 목록의 그룹 기준만 변경. 전역 저장 전에는 미저장 |
| 인력 상세·등록 | 목록/일정에서 해당 인력 → 기본·추가 정보 → 적용 | 이름·업체·기간 일치. 원래 화면/상위 팝업으로 복귀 |
| TBD 확정 전환 | TBD 상세 → 이름·필수 정보·실제 날짜 → 적용 | ID와 모든 안의 유효한 배치 유지, M/M 중복 없음 |
| 대표 철수·삭제·분류 변경 | 인계 자격 평가 → 한 명 자동/여러 명 선택 → 원 작업 적용 | 취소 시 원 작업·인계 모두 반영하지 않음. 다른 대표 지정과 인력 분류는 보존 |
| 역할·기술이 빈 TBD 선임 시도 | 후보에서 제외하고 필요 항목 안내 | 일반 TBD 등록·그룹 리더 자격은 유지 |
| 기본 설정 편집 | 해당 탭 → 항목 편집 → 적용 | 참조 ID 유지·사용 안 함 기존 표시 보존·업체 타입 잠금 준수 |

- Figma의 조건 화면·레이아웃 검토와 실제 앱의 기능 검증은 별도다. 12절의 검증은 개발한 앱에서 수행해야 한다.
